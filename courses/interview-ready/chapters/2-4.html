The signal

"Find the minimum X such that something is possible" or "the maximum Y such that…", especially minimise the maximum or maximise the minimum, with a large numeric answer range (speeds, capacities, distances, times). If checking a single candidate answer is easy (often a greedy pass) and feasibility is monotone in the answer, binary-search the answer.

The core idea

Swap the optimisation for a decision problem. "What's the least capacity that ships everything in D days?" is hard; "can capacity C ship everything in D days?" is a greedy O(n) check. If capacity C works, any C′ > C works too: the predicate "C is feasible" is monotone in C. So the answer is the first true of a monotone predicate over the answer range, and Chapter 2.3's template finds it in O(log(range)) checks.

Cost: O(check × log(range)). For a range up to 10⁹ that's 30 checks.

The invariant and template

lo, hi = smallest_possible, largest_possible   # hi must be feasible
while lo < hi:
    mid = (lo + hi) // 2
    if feasible(mid): hi = mid
    else: lo = mid + 1
return lo

Three decisions, in order: (1) the answer range: a bound you can prove is infeasible-or-minimal (often max(element)) and one certainly feasible (often the sum); (2) the check, usually greedy, with a short argument why greedy is right for a fixed candidate; (3) confirm monotonicity in one sentence.

A thinking trace: split array largest sum

  1. Problem: split into k contiguous parts minimising the largest part's sum.
  2. First idea: DP over (position, parts): O(k n²). Correct, and worth saying.
  3. Signal: "minimise the maximum". Fix a cap S: can we split into at most k parts each ≤ S? Greedily extend each part until the next element would exceed S. Greedy is right because ending a part earlier never helps later parts.
  4. Monotone: a larger S needs no more parts.
  5. Range: S ∈ [max(nums), sum(nums)]: below max, some element can't fit; at sum, one part suffices.
  6. Cost: O(n log sum). And notice it's the shipping problem with different words: recognising equivalent problems is the payoff of pattern training.

Traps and variations

  • Real-valued answers (minimise a maximum distance): binary-search on floats for a fixed number of iterations (e.g. 100) instead of while lo < hi.
  • Maximise the minimum (aggressive cows, magnetic balls): search for the last feasible value, or negate the predicate.
  • Median of two sorted arrays: binary search on a partition rather than a value, the same "guess and check which direction" logic.
  • k-th smallest in a sorted matrix or of pairwise distances: binary-search the value and count elements ≤ it.
