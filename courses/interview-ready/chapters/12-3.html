The signal

"How would you train a 70B model?", "what's ZeRO?", "why does this job get 30% MFU?", "how much memory does Adam need?", "estimate the training time". The core skill is a memory and communication budget per GPU for each parallelism strategy.

The core idea: memory per parameter, FLOPs per token, bytes per step

Training FLOPs ≈ 6 × P × tokens (2 forward + 4 backward per parameter per token). Mixed-precision Adam memory ≈ 16 bytes per parameter: BF16 weights (2) + BF16 gradients (2) + FP32 master weights (4) + Adam m and v (4 + 4). Activations come on top, reduced by activation checkpointing (recompute in the backward pass).

Real large jobs use 3D/4D parallelism: TP inside a node, PP across a few nodes, DP/FSDP across the rest.

The invariant and template: training envelopes

train_FLOPs      = 6 · P · T
time             = train_FLOPs / (N_gpus · MFU · peak)
state_bytes      = 16 · P                          (÷ N with ZeRO-3/FSDP)
ring all-reduce  : each GPU sends/receives 2·(n−1)/n · S bytes  → time ≈ 2·S / link_bw for large n
pipeline bubble  ≈ (p − 1) / (m + p − 1)           (p stages, m micro-batches)
MFU              = achieved model FLOPs / peak     (good: 40–55% on H100-class at scale)

A thinking trace: plan a 7B pre-training run

  1. Compute: 6 × 7 × 10⁹ × 2 × 10¹² tokens = 8.4 × 10²² FLOPs.
  2. Time: on 1,024 H100s at 40% MFU: 8.4 × 10²² / (1,024 × 0.4 × 989 × 10¹²) ≈ 2.1 × 10⁵ s ≈ 2.4 days.
  3. Memory: 16 × 7 × 10⁹ = 112 GB of state, which doesn't fit in 80 GB. Use FSDP/ZeRO-3 across 8 GPUs → 14 GB per GPU for state, leaving room for activations (with checkpointing).
  4. Communication: gradients are 14 GB in BF16. A ring all-reduce over 8 GPUs moves 2 × 7/8 × 14 GB ≈ 24.5 GB per GPU, about 55 ms at ~450 GB/s NVLink per direction. Across nodes (~50 GB/s per GPU on 400 Gb/s InfiniBand) it's 10× slower, so overlap communication with the backward pass and use hierarchical reduction.
  5. Parallel layout: a 7B model doesn't need TP or PP. Use FSDP within nodes and data parallelism across 128 nodes; the global batch is ~4M tokens.
  6. Failure planning: at 1,024 GPUs, expect failures within hours to days. Checkpoint regularly (asynchronously, to fast storage) and automate restarts.

The habit: FLOPs for time, 16 bytes/param for memory, 2S/bw for communication. Then pick the least-communicating parallelism that fits.

Traps and variations

  • Activations dominate at long sequence lengths: recompute (checkpointing), or use sequence parallelism.
  • Small per-GPU batches lower MFU (kernels become inefficient). There's tension between global batch size (convergence) and per-GPU efficiency.
  • Stragglers: synchronous training runs at the speed of the slowest GPU. Monitor per-rank step times.
  • MoE models: parameter count ≠ FLOPs per token (only the active experts compute); expert parallelism adds all-to-all communication.
  • Numerics: BF16 range vs FP16 overflow; loss scaling for FP16; FP8 training needs per-tensor scaling.
