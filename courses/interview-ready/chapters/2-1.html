The signal

A stack is the right tool when the most recent unfinished thing must be finished first: matching brackets, nested structures (expressions, encodings, directory paths, HTML tags), undo histories, and depth-first search done by hand. If you find yourself writing "go back to the last place where…", it's a stack.

The core idea

Push when something opens; pop when it closes, and check the pop matches. At any moment the stack holds exactly the open, unresolved items, innermost on top. That single invariant solves bracket matching, expression evaluation and decoding. For nesting with state (decode-string's partial results and repeat counts), push a frame: everything you need to resume the outer level when the inner one ends. That's precisely what a call stack does for recursion, which is why every stack algorithm can be written recursively and vice versa.

The invariant and template

stack = []                      # invariant: unresolved openers / frames, innermost on top
for token in input:
    if opens(token): stack.append(frame_for(token))
    elif closes(token):
        if not stack or not matches(stack[-1], token): return invalid
        frame = stack.pop(); combine frame with the finished inner result
    else: extend the current (innermost) result
return result if not stack else invalid

Two checks people forget: popping from an empty stack (a closer with no opener) and a non-empty stack at the end (an opener never closed).

A thinking trace: decode string

  1. Example: 3[a2[c]]. By hand: I find the innermost bracket, expand it (cc), then expand the outer (acc × 3). Innermost first: a stack.
  2. Brute force: repeatedly find an innermost k[…] with a regex and replace it: correct, but O(n²) or worse in rescanning.
  3. Bottleneck: rescanning the string after each expansion.
  4. Transformation: scan once; on [ push the frame (text before it, repeat count) and start a fresh current string; on ] pop and set current = saved + current × k.
  5. Edge cases: multi-digit counts (10[x]: accumulate digits), letters after a bracket (2[a]bc), nesting several deep.

Traps and variations

  • Operand order in RPN: pop b first, then a, and compute a − b, a / b.
  • Truncating division: Python's // floors (−7 // 2 = −4); most problems want truncation toward zero: int(a / b).
  • Infix expressions (calculator problems): two stacks (operands and operators) with precedence, or recursive descent; the shunting-yard algorithm converts to RPN.
  • Stacks with extra queries (min-stack): store per-element auxiliary data that summarises everything below it, so pops never need recomputation.
