The signal

Prefix sums answer anything about contiguous ranges of an array, fast: range sums, counts of subarrays with a property, averages over windows, or "how many elements in [l, r] satisfy…". The brute force recomputes a sum over each range from scratch; prefix sums compute each range in O(1) after O(n) preprocessing. The mirror image, the difference array, handles many range updates followed by reads.

The core idea

Let $P[0] = 0$ and $P[k] = a_0 + \dots + a_{k-1}$. Then

$$\sum_{t=i}^{j} a_t = P[j+1] - P[i].$$

Two consequences power most problems:

  • A subarray condition becomes a condition on two prefixes. "Subarray (i, j] sums to k" ⇔ "$P[j] - P[i] = k$" ⇔ "$P[i] = P[j] - k$": combine with a hash map of earlier prefixes (Chapter 1.1) to count them in one pass.
  • Any associative, invertible operation works. Sums, XORs (XOR is its own inverse), counts; products if no zeros (or use prefix and suffix products, as in product-except-self). Modular sums: "sum divisible by k" ⇔ equal prefix sums mod k.

The invariant and template

count = 0; prefix = 0
seen = Counter({0: 1})          # invariant: seen counts prefixes P[0..j] for the j processed so far
for x in nums:
    prefix += x                 # prefix = P[j + 1]
    count += seen[prefix - k]   # earlier prefixes P[i] with P[j+1] − P[i] = k
    seen[prefix] += 1

The seed {0: 1} is the empty prefix, so subarrays starting at index 0 count. Forgetting it is the classic bug.

Difference array: to add v to every element of [l, r], do d[l] += v; d[r+1] -= v; after all updates, the prefix sum of d gives the values. Many updates, one read: O(updates + n).

A thinking trace: subarray sum equals k

  1. Clarify: values can be negative (this matters!), count subarrays, not just find one.
  2. Brute force: all (i, j) pairs with a running sum: O(n²).
  3. Why not a sliding window? Windows need monotonicity: growing the window must only increase the sum. Negative values break that, so a window can't decide when to shrink. Saying this out loud shows you know when a pattern doesn't apply.
  4. Bottleneck: for each end j, we search all starts i for $P[i] = P[j+1] - k$: a search, so a hash map.
  5. Invariant and complexity: as in the template, O(n) time and space.
  6. Tests: [1, −1, 0] with k = 0 has 3 subarrays ([1, −1], [0], [1, −1, 0]); empty array gives 0.

Traps and variations

  • Overflow: prefix sums can exceed 32 bits even when elements don't. Use 64-bit in C++.
  • Off-by-one: always use the "P has n + 1 entries, P[0] = 0" convention; then every range is P[r+1] − P[l] with no special cases.
  • 2-D prefix sums: $S[r][c]$ = sum of the rectangle above-left; a rectangle sum is four lookups (inclusion–exclusion).
  • Variations: longest subarray with sum k (store the first index of each prefix), equal numbers of 0s and 1s (map 0 → −1, then sum zero), subarray sums divisible by k (prefixes mod k).
