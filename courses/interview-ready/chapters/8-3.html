The signal

"O(1) extra space", "without using + or −", "every element appears twice/three times except…", "power of two", "subsets of a small set", "XOR of a range", Gray codes, hardware-ish questions about flags and masks. Also performance engineering in general: bit tricks are how compilers and GPU kernels avoid branches. Know the identities cold, because a bit-trick question is usually short and graded on fluency.

The core idea: per-bit arithmetic

Bitwise operations act on each bit independently. Many problems become easy when you think one bit position at a time:

  • XOR is addition mod 2 per bit, so pairs cancel: x ^ x = 0, x ^ 0 = x. The XOR of everything leaves the odd-count element.
  • Generalise the modulus: with "three times except one", count each bit mod 3. The ones/twos trick is a 2-bit counter per position.
  • XOR has an inverse (itself), so prefix XORs work like prefix sums: XOR(l..r) = P[r+1] ^ P[l].
  • The lowest set bit is x & −x (two's complement), and x & (x − 1) clears it. That's the Fenwick tree's engine and Kernighan's popcount.
  • Addition without +: sum = a ^ b (no carry), carry = (a & b) << 1; repeat until no carry.

Python caveat: integers are unbounded, so ~x is −x − 1 and there's no overflow. To emulate 32-bit behaviour, mask with 0xFFFFFFFF and convert back: x if x < 2**31 else x - 2**32.

A thinking trace: single number II

  1. Easy answers first: a hash-map count is O(n) time and space. Sort, then step by 3: O(n log n). Both are fine, but O(1) space is the ask.
  2. Why plain XOR fails: three copies XOR to the value itself, not 0.
  3. Think per bit: at bit position i, the count of numbers with bit i set is 3k + (the single number's bit). So count mod 3 recovers each bit. That's 32 passes, O(32n), and O(1) space.
  4. Compress the counter: keep the per-bit count mod 3 in two words (ones, twos): ones = (ones ^ x) & ~twos; twos = (twos ^ x) & ~ones. Trace one bit through the states 0 → 1 → 2 → 0 to convince yourself.
  5. Negatives: in C++ this just works on 32-bit ints. In the per-bit Python version, reconstruct the sign from bit 31.

The move: when a whole-number trick fails, decompose into bits and solve per bit. Maximum XOR pairs (binary trie), the sum of pairwise Hamming distances, and the bitwise AND of a range all use it.

Traps and variations

  • Precedence: in C/C++ and Python, comparison binds tighter than &, so x & 1 == 0 is x & (1 == 0). Parenthesise.
  • Shifting into the sign bit or by ≥ the width is undefined behaviour in C++. Use 1LL << i for i ≥ 31, and unsigned types for bit manipulation.
  • Total Hamming distance: per bit, count c ones among n numbers; that bit contributes c·(n − c). O(32n) instead of O(n²).
  • Bitwise AND of a range [m, n]: the common prefix of m and n; shift both right until equal.
  • Single number III (two odd ones out): XOR everything, split by any set bit of the result, XOR each group.
  • Subsets as masks and iterating over submasks: see Part 7.
