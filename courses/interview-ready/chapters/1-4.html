The signal

A contiguous subarray or substring that is the "longest", "shortest" or "count of" something satisfying a condition, where adding elements makes the condition monotonically harder (or easier) to satisfy. The brute force examines every window: O(n²) windows, often each in O(n). A sliding window examines O(n) windows, updating its state incrementally as one element enters and one leaves.

The core idea

Keep a window [left, right]. Move right forward one step at a time; after each step, move left forward just enough to restore validity (for "longest valid window") or as far as possible while still valid (for "shortest valid window"). Keep the window's state (counts, sum, distinct characters) up to date in O(1) per move.

It works only under monotonicity: if a window is invalid, every larger window containing it is invalid too (e.g. "has a repeated character", "sum exceeds k with positive numbers"). Then left never needs to move backwards. Without monotonicity (negative numbers in sum problems) the window can't decide when to shrink, and you need prefix sums instead (Chapter 1.2).

The invariant and template

left = 0; state = empty; best = 0
for right, x in enumerate(s):
    add x to state
    while window [left, right] is invalid:   # restore the invariant
        remove s[left] from state; left += 1
    # invariant: s[left..right] is the longest valid window ending at right
    best = max(best, right - left + 1)

For "shortest window containing…" flip it: while the window is valid, record it and shrink. The O(n) proof is amortised: left and right each move at most n times in total.

A thinking trace: minimum window substring

  1. Clarify: t may have repeated characters (multiplicity counts); return the window, not its length; "" if none.
  2. Brute force: every window, checking counts: O(n² · alphabet).
  3. Monotonicity: a window containing all of t stays valid when enlarged. So for each right end, the best left is the largest one still valid, and it only moves forward.
  4. State: need[c] = how many more c the window needs (negative = surplus), and missing = total still needed, so validity is missing == 0: O(1).
  5. Loop: extend right; when valid, advance left past surplus characters, record, then give up one needed character to search for the next window.
  6. Complexity: O(|s| + |t|). Tests: t longer than s, t with repeats ("aa" in "a"), the answer at the very end.

Traps and variations

  • Fixed-size windows (size k): add the new element, remove the one k back; no while loop.
  • Window maximum or minimum: the state can't be a single number (removal is hard); use a monotonic deque of indices with decreasing values: each index is pushed and popped once.
  • "At most k distinct" counting trick: the number of subarrays with exactly k distinct = atMost(k) − atMost(k − 1), each a sliding window.
  • Stale state is sometimes fine: in longest repeating replacement, the max frequency never needs to decrease, because the answer only improves when it grows.
