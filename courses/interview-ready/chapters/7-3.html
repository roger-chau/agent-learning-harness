The signal

Two DP families that look different but share an idea: the structure of the input tells you the order of the DP.

  • Tree DP: optimise or count over a tree: independent sets, vertex covers, cameras, the longest path, "for every node, compute X over the whole tree" (the last is rerooting).
  • Digit DP: "how many integers in [L, R] have property P" with R up to 10¹⁸. You can't iterate the numbers, but you can walk their digits.

The core idea

Tree DP is Part 3's recursive contract with more states: f(v) returns a small tuple, such as (best if v is taken, best if not), and the parent combines its children's tuples. Post-order is the topological order.

Rerooting answers "for every root" in O(n) instead of O(n²). Compute the answer for one root bottom-up, then move the root across each edge with an O(1) correction. For the sum of distances: moving from p to its child c brings size[c] nodes one step closer and sends n − size[c] nodes one step farther.

Digit DP builds numbers from the most significant digit with a tight flag: while the prefix equals N's prefix, the next digit is capped by N's digit. Once it's smaller, every later digit is free (0–9). Add whatever the property needs to the state (a digit sum, a used-digit mask, the previous digit), plus a started flag for leading zeros. Count [L, R] as f(R) − f(L − 1).

The invariant and template

# Tree DP, iterative post-order (no recursion limit)
order, parent = dfs_order(root)
for v in reversed(order):              # children before parents
    take[v] = val[v] + sum(skip[c] for c in children(v))
    skip[v] = sum(max(take[c], skip[c]) for c in children(v))

# Digit DP
@cache
def go(i, tight, started, state):
    if i == len(s): return accept(state, started)
    hi = int(s[i]) if tight else 9
    return sum(go(i + 1, tight and d == hi, started or d > 0, step(state, d, started)) for d in range(hi + 1))

Invariant (digit DP): go(i, tight, …) counts completions of the first i digits that stay ≤ N. Memoising over tight = False states is what makes it fast; tight = True occurs on only one path.

A thinking trace: sum of distances in a tree

  1. Brute force: BFS from every node, O(n²). That's 9 × 10⁸ for n = 3 × 10⁴: too slow.
  2. One root first: root at 0. Post-order gives size[v] and down[v] (the sum of distances from v into its subtree): down[v] = Σ over children of (down[c] + size[c]). ans[0] = down[0].
  3. What changes when the root moves to child c? The size[c] nodes in c's subtree each get 1 closer; the other n − size[c] each get 1 farther. So ans[c] = ans[p] − size[c] + (n − size[c]).
  4. Pre-order pass applies it top-down: O(n) total.
  5. Test: a single node (0), a path (the endpoints have the largest sums), and a star.

The move: solve for one configuration, then find the O(1) delta to a neighbouring configuration. Rerooting, sliding windows and the "move the median" arguments are all this.

Traps and variations

  • Recursion depth on path-shaped trees: use an iterative order, especially in Python.
  • Undirected input: track the parent to avoid walking back up.
  • Binary tree cameras: three states per node (has a camera, covered, needs cover), decided greedily from the leaves.
  • Diameter of a general tree: two BFS passes, or the tree-DP top-two child heights.
  • Digit DP traps: forgetting the started flag (leading zeros counted as digits), and computing f(L − 1) wrongly when L = 0.
  • Closed forms instead: counting 1s has a per-position formula; numbers with distinct digits below 10ᵏ is a product of permutations. Use the formula when you can derive it, and the DP when the property is messy.
Maths shortcut. Many digit-DP counts have closed forms: numbers below 10ᵏ with distinct digits are 9·9·8·… products, and the count of digit 1 has a per-position formula. Derive the formula when the property is simple; use the DP when it isn't.
