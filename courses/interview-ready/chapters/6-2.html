The signal

A grid where movement goes in one general direction (right and down, or row by row), asking for a count of paths, a best path sum, or the largest square or rectangle. One-directional moves make the grid a DAG, so DP in row-major order is valid. If moves can go back (all four directions), it's a graph search instead: BFS or Dijkstra from Part 4.

The core idea

The state is a cell, and the transition reads the cells you could have come from. Three choices make or break grid DP:

  • What the state anchors to: "paths into (i, j)", "the best square with its bottom-right corner at (i, j)", "the health needed when entering (i, j)". Anchoring the substructure to a corner or endpoint is what makes the transition local.
  • Direction: forward (from the start) or backward (from the goal). Choose the direction in which the state is a single number with optimal substructure.
  • Memory: a row only reads the previous row (and itself), so one array of length C is enough. Mind the update order within the row.

The invariant and template

# Forward, rolling one row. Before updating dp[j], dp[j] = the value above and dp[j-1] = the value to the left (already updated).
dp = [INIT] * C
for i in range(R):
    for j in range(C):
        dp[j] = combine(grid[i][j], dp[j], dp[j - 1] if j else NONE)

# Square anchored at the bottom-right corner
side[i][j] = 1 + min(side[i-1][j], side[i][j-1], side[i-1][j-1])  if grid[i][j] == '1' else 0

Padding the table with an extra row and column of base values removes the boundary ifs. In C++ it also avoids reading index −1.

A thinking trace: dungeon game

  1. First idea, forward: dp[i][j] = the maximum health left on reaching (i, j). Attack it: one path arrives with 10 health but needed a starting health of 8; another arrives with 3 and needed only 2. Which is better? It depends on what comes next. A single forward number doesn't capture the trade-off between current health and the worst dip so far.
  2. Diagnose: the forward state needs two numbers that conflict. That's a sign the direction is wrong.
  3. Reverse: need[i][j] = the minimum health on entering (i, j) to survive to the end. It depends only on the future, which has optimal substructure: need[i][j] = max(1, min(need[i+1][j], need[i][j+1]) − d[i][j]).
  4. Base: the cells beyond the princess need 1 (pad the table and set the two neighbours of the exit to 1).
  5. Order: bottom-right to top-left. The answer is need[0][0].
  6. Test: a single positive cell (1), a single −5 (6), and a big reward late in the path that can't save you from an early dip.

The move: when a forward state needs two competing numbers, try the backward direction, where the constraint becomes local. The same idea appears in the "minimum initial fuel or balance" problems in quant interviews.

Traps and variations

  • Obstacles on the first row or column block everything after them. With a rolling array this is automatic; with explicit base loops it's a classic bug.
  • Counting overflow: unique paths in an m × n grid is C(m + n − 2, m − 1), which overflows 32 bits quickly. Use 64 bits or a modulus.
  • Cherry pickup: two walkers moving together form one DP over (step, row₁, row₂). Never do two separate greedy passes.
  • Maximal rectangle: build histogram heights row by row, then run the Part 2 monotonic-stack histogram on each row: O(RC).
  • Triangle: bottom-up from the base needs only one row and no special cases.
  • Four-directional movement means it isn't a DAG and DP is invalid (it would be cyclic). Use Dijkstra.
