The signal

Dynamic programming fits when a problem asks for the best value, the number of ways, or whether it's possible, and the brute force makes a sequence of choices whose futures overlap. Two tests settle it:

  • Optimal substructure: an optimal answer is built from optimal answers to smaller versions of the same question.
  • Overlapping subproblems: the brute-force recursion asks the same smaller question many times. Draw the recursion tree for a small input and look for repeated nodes.

Two common traps: if a greedy works you don't need DP (but prove it, Part 5), and if subproblems never repeat, plain recursion or divide and conquer is enough.

The core idea: the five questions

Every DP solution answers five questions. Answer them in words, out loud, before writing code. That turns DP from guesswork into a procedure.

  1. State: what does dp[i] mean, in one exact sentence? ("dp[i] = the fewest coins summing to i.")
  2. Transition: how is dp[i] built from smaller states? Usually by asking "what was the last choice?"
  3. Base cases: the smallest states, answered directly.
  4. Order: compute each state after everything it depends on.
  5. Answer: which state, or which max over states, is the final answer?

Two implementations of the same idea: top-down (recursion plus a memo; fast to write and only visits reachable states) and bottom-up (loops over a table; no recursion limit, and easy to shrink to O(1) or O(row) memory). In Python interviews, write the top-down version when you're unsure of the order, and convert if depth or speed matters.

The invariant and template

from functools import cache
@cache
def f(i):                       # state: one sentence, written above the function
    if i < 0: return BAD        # base cases
    if i == 0: return BASE
    return best(f(i - step) + cost(step) for step in choices(i))   # last choice
answer = f(n)

# Bottom-up: the same recurrence, in dependency order
dp = [BASE] + [INIT] * n
for i in range(1, n + 1):
    for step in choices(i):
        dp[i] = best(dp[i], dp[i - step] + cost(step))

Invariant: when dp[i] is computed, every dp[j] it reads is final. Space: if dp[i] reads only dp[i−1] and dp[i−2], keep two variables (house robber).

A thinking trace: longest increasing subsequence

  1. State, first attempt: dp[i] = the length of the LIS ending exactly at i. Why "ending at"? Because extending a subsequence needs to know its last element. A state of "the best within the first i elements" loses that information.
  2. Transition: dp[i] = 1 + max(dp[j] for j < i if a[j] < a[i]), with base 1. The answer is max(dp), because the LIS can end anywhere. That's O(n²).
  3. Bottleneck: the inner max scans all j. For n = 10⁵ that's 10¹⁰ operations.
  4. Change the state: for each length L, keep the smallest tail of any increasing subsequence of length L. A smaller tail dominates a larger one: anything that extends the larger also extends the smaller.
  5. Structure: tails is strictly increasing (prove it by contradiction), so finding where x goes is a binary search, and each x updates exactly one entry. That's O(n log n).
  6. Test: strictly increasing (n), all equal (1, so use bisect_left because the subsequence must be strictly increasing), and strictly decreasing (1).

The lessons: "ending at i" states keep the information a transition needs, and dominance ("this partial solution is never worse than that one") lets you throw states away, often turning O(n²) into O(n log n).

Traps and variations

  • The sentinel versus infinity: in coin change, amount + 1 means impossible and avoids float('inf') and int overflow.
  • Answer is max over all states (LIS, maximum subarray), not the last state. Read your state sentence to decide.
  • Memo with mutable arguments: @cache needs hashable arguments, so pass indices, not lists.
  • Recursion depth: top-down on n = 10⁵ overflows in Python. Go bottom-up.
  • Decode ways: dp[i] = dp[i−1] (if s[i−1] ≠ '0') + dp[i−2] (if s[i−2:i] is 10–26). The zeros are the entire difficulty.
  • House robber II (circular): run the linear version twice, excluding the first house, then the last.
  • Maximum subarray (Kadane): dp[i] = max(a[i], dp[i−1] + a[i]). It's a one-dimensional DP that looks like a greedy.
Maths shortcut. Climbing stairs and house-robber-like recurrences are linear recurrences: for n up to 10¹⁸ use a matrix power in O(log n) (Part 8.5). Coin change with two coprime coins a, b can make every amount above ab − a − b (the Frobenius number).
