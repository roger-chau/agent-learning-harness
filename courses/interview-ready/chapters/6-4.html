The signal

Two strings (or arrays), a question about how they align: the longest common subsequence, edit distance, interleaving, matching with wildcards or regular expressions, counting occurrences as a subsequence. Also one string compared with itself (palindromic subsequences). Expect a table indexed by a prefix of each, with O(mn) time.

The core idea: look at the last characters

State: dp[i][j] = the answer for a[:i] and b[:j]. Transition: look at a[i−1] and b[j−1] and ask what can happen to them.

  • Both used together (match or substitute): from dp[i−1][j−1], the diagonal.
  • a's character is dropped (deleted or skipped): from dp[i−1][j], above.
  • b's character is dropped (inserted or skipped): from dp[i][j−1], the left.

Every two-sequence DP is a choice of which of these three moves are allowed and what each costs. The base row and column answer "against the empty string". Draw the table for two short strings. The arrows are the recurrence, and the table is a DAG of the alignments.

The invariant and template

prev = [base(0, j) for j in range(m + 1)]          # row i = 0
for i in range(1, n + 1):
    cur = [base(i, 0)] + [0] * m
    for j in range(1, m + 1):
        if a[i-1] == b[j-1]:
            cur[j] = diag_on_match(prev[j-1])
        else:
            cur[j] = combine(prev[j-1] + sub, prev[j] + dele, cur[j-1] + ins)
    prev = cur

A thinking trace: edit distance

  1. Clarify: three operations, each costing 1. Transforming a into b is symmetric to b into a (insertion and deletion swap roles).
  2. State: dp[i][j] = the minimum operations turning a[:i] into b[:j].
  3. Last characters: if they're equal, no operation is needed for them: dp[i−1][j−1]. Otherwise the last step is one of: substitute (↖ + 1), delete a's last (↑ + 1), or insert b's last (← + 1).
  4. Why is that exhaustive? In any optimal edit script, a[i−1] is either kept or deleted. If kept, it is matched with b[j−1] (equal or substituted), or b[j−1] was inserted after it. Those are the three cases. Being able to say this is what proves the recurrence.
  5. Base: dp[i][0] = i (delete everything) and dp[0][j] = j (insert everything).
  6. Memory: two rows. The full table is needed only to reconstruct the edits.
  7. Test: "horse" → "ros" is 3, and the empty string against "abc" is 3.

The habit: justify the recurrence with a case split on what happens to the last element, and check that the cases are exhaustive and don't overlap (essential for counting problems).

Traps and variations

  • Off-by-one indices: dp has dimensions (n + 1) × (m + 1), and dp[i][j] reads a[i−1]. Write that down at the top of the code.
  • Rolling arrays need the diagonal: with one row, save the old dp[j−1] before overwriting it, or keep two rows.
  • Counting must not double-count: distinct subsequences adds two disjoint cases (use s[i−1] or not). LCS-style max can overlap freely, but counts can't.
  • Longest common substring (contiguous): dp[i][j] = 1 + dp[i−1][j−1] on a match, else 0, and the answer is the max over the table. Don't confuse it with the subsequence version.
  • Regular expression and wildcard matching: the same table, with '*' allowing ↑ (match one more) or a skip. Quant firms ask these.
  • Interleaving string: dp[i][j] = whether a[:i] and b[:j] interleave into c[:i+j]. A boolean two-sequence DP.
  • Large inputs: LCS of two 10⁵-length strings is 10¹⁰ cells, which is too many. Special structure (such as permutations, which reduce to LIS in O(n log n)) is the way out.
