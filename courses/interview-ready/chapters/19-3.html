The signal

Quant-dev rounds mix classic \"brainteasers in code\": implement rand7() from rand5(), shuffle uniformly, sample k items from a stream of unknown length, simulate a game to check a probability, generate correlated normals. Each tests whether your code is exactly correct in distribution, which is hard to see by eye.

The core idea: prove uniformity, then test it statistically

  • Fisher–Yates shuffle: for i from n − 1 down to 1, swap a[i] with a[j], j uniform in [0, i]. That gives n! equally likely outcomes. The common bug (j uniform in [0, n − 1] every time) gives nⁿ outcomes, which can't map evenly onto n!.
  • Rejection sampling: rand7 from rand5: form 5·(rand5 − 1) + rand5, uniform on 1..25; accept 1..21 (21 = 3 × 7) and map mod 7; reject 22–25 and retry. Expected calls = 2 × 25/21 ≈ 2.38.
  • Reservoir sampling: keep the first k items; for item i > k, replace a random reservoir slot with probability k/i. Every item ends up included with probability k/n, proved by induction.
  • Correlated normals: Z₁ and Z₂ independent; X = Z₁, Y = ρZ₁ + √(1 − ρ²)Z₂ (Cholesky).
  • Testing: run 10⁶ trials and compare counts with expectations using a chi-square test. A biased shuffle shows up immediately for n = 3.

The invariant and template

def shuffle(a, rng):                    # invariant: a[i:] is a uniform random arrangement of chosen items
    for i in range(len(a) - 1, 0, -1):
        j = rng.randint(0, i)
        a[i], a[j] = a[j], a[i]

def reservoir(stream, k, rng):          # invariant: each of the first i items is in R with probability k/i
    R = []
    for i, x in enumerate(stream, 1):
        if i <= k: R.append(x)
        else:
            j = rng.randint(1, i)
            if j <= k: R[j - 1] = x
    return R

A thinking trace: "is this shuffle uniform?"

for i in range(n): j = randint(0, n - 1); a[i], a[j] = a[j], a[i]
  1. Count outcomes: each step has n choices, so nⁿ equally likely execution paths.
  2. Divisibility: for the result to be uniform over n! permutations, n! must divide nⁿ. For n = 3: 27 isn't divisible by 6. Not uniform.
  3. Which permutations are favoured? For n = 3, some arrangements appear 5 times out of 27 and others 4 (not 4.5). Confirm with a quick simulation.
  4. Fix: Fisher–Yates, j in [0, i]: n × (n − 1) × … × 1 = n! paths, one per permutation.

The habit: count the equally likely execution paths and check that they divide evenly among the outcomes, then confirm with a chi-square test.

Traps and variations

  • Modulo bias: rand() % n is biased unless n divides RAND_MAX + 1. Use rejection or std::uniform_int_distribution.
  • Seeding: reproducible simulations need explicit seeds; parallel simulations need independent streams.
  • Monte Carlo error: SE ∝ 1/√N. Report it with every simulated probability.
  • Weighted sampling: alias method for O(1) per sample after O(n) set-up; prefix sums + binary search for O(log n).
