The signal

Exponents or indices up to 10¹⁸ ("the n-th term", "after n steps", "aⁿ mod m"); divisibility, primes, gcd and lcm; "multiples of a or b"; periodic behaviour; huge counts mod a prime. If a loop would run n = 10¹⁸ times, the intended solution is O(log n) via repeated squaring, or O(1) via a formula.

The core idea: squaring halves the exponent

aⁿ = (a^(n/2))² for even n, and a · a^(n−1) for odd n. So read n in binary, squaring the base at each bit and multiplying it into the result when the bit is 1. That's O(log n) multiplications. It works for anything with an associative multiplication: numbers mod m, matrices, permutations, even function composition.

Linear recurrences become matrix powers. If the state vector vₜ₊₁ = A·vₜ (Fibonacci: [[1, 1], [1, 0]]), then vₙ = Aⁿ·v₀, computed in O(k³ log n) for a k × k matrix. Counting paths of length n in a graph is the adjacency matrix to the n-th power.

Number theory essentials: Euclid's gcd(a, b) = gcd(b, a mod b) in O(log); lcm = a / gcd · b (divide first to avoid overflow); the sieve of Eratosthenes for all primes up to n in O(n log log n); trial division up to √n for one number's factors; Fermat inverses for primes.

The invariant and template

def power(a, n, mod):          # invariant: result · a^n = original a^n
    result = 1; a %= mod
    while n:
        if n & 1: result = result * a % mod
        a = a * a % mod
        n >>= 1
    return result
# Python: pow(a, n, mod) is built in, and pow(a, -1, mod) gives an inverse (3.8+).

def gcd(a, b):
    while b: a, b = b, a % b
    return a

def sieve(n):                  # is_prime[0..n-1]
    s = bytearray([1]) * n; s[0:2] = b"\x00\x00"
    for i in range(2, int(n**0.5) + 1):
        if s[i]: s[i*i::i] = bytearray(len(range(i*i, n, i)))
    return s

A thinking trace: the n-th magical number

  1. Brute force: walk the multiples of a and b in merged order, n steps. With n = 10⁹ that's too slow.
  2. Change the question from "what is the n-th?" to "how many are ≤ x?" That count is easy: multiples of a, plus multiples of b, minus the double-counted multiples of both, which are the multiples of lcm(a, b) (inclusion–exclusion).
  3. Monotone count, so binary search the smallest x with count(x) ≥ n. The range is [1, n·min(a, b)], about 60 iterations.
  4. lcm: a·b / gcd(a, b), with gcd by Euclid.
  5. Modulus at the end only: reducing x mod 10⁹+7 inside the search would break the comparisons.

The move, again: "find the k-th" becomes "count ≤ x" plus binary search (Part 2), and the counting step is where the maths goes.

Traps and variations

  • Overflow in C++: a·b with both near 10⁹ needs 64 bits; with a 64-bit modulus use __int128 or mulmod.
  • pow(x, n) for real x with negative n: invert the base, and careful with n = INT_MIN in C++ (−n overflows).
  • Fermat inverse needs a prime modulus. Otherwise use the extended Euclidean algorithm (it exists iff gcd(a, m) = 1).
  • Cycle detection instead of matrix power: sequences like xₙ₊₁ = f(xₙ) mod m eventually repeat (Floyd from Part 3), so find the cycle and index into it.
  • Super pow (a^(huge exponent given as digits)): use a^(10q + r) = (a^q)^10 · a^r recursively.
  • Quant connection: Markov chain n-step probabilities are matrix powers, and the stationary distribution is the long-run limit (Part 14).
