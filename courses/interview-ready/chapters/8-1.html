The signal

Many range queries interleaved with updates: "sum / min / max / gcd over [l, r]" while values change, or counting "how many earlier elements are smaller than x" (inversions, count-smaller-after-self, ranking in a stream). Static data needs only prefix sums or a sparse table; it's the mix of updates and queries, each up to 10⁵, that calls for an O(log n) tree.

The core idea: precompute sums over power-of-two blocks

Both trees store the answer for O(n) carefully chosen blocks so that any range is a union of O(log n) blocks and any position lies in O(log n) blocks. A query combines the blocks covering the range; an update fixes the blocks containing the position.

Fenwick: entry i covers the (i & −i) positions ending at i. Prefix queries walk down by clearing the lowest bit; updates walk up by adding it. It needs an invertible operation (sum, XOR) for range queries, as prefix(r) − prefix(l − 1).

Segment tree: a binary tree over [0, n); each node stores the combine of its range. It works for any associative operation, and supports range updates via lazy tags: a fully covered node records the pending update instead of passing it to all its descendants.

Coordinate compression makes value-indexed trees possible when values are up to 10⁹: sort the distinct values and replace each by its rank.

The invariant and template

class BIT:                                   # 1-indexed
    def __init__(self, n): self.n = n; self.t = [0] * (n + 1)
    def add(self, i, d):                     # position i (1..n) += d
        while i <= self.n: self.t[i] += d; i += i & -i
    def prefix(self, i):                     # sum of 1..i
        s = 0
        while i > 0: s += self.t[i]; i -= i & -i
        return s

# Segment tree (iterative, point update, range min). Leaves at [size, 2·size).
def update(i, v):
    i += size; t[i] = v
    while i > 1: i //= 2; t[i] = min(t[2*i], t[2*i+1])
def query(l, r):                             # inclusive l, exclusive r
    res = INF; l += size; r += size
    while l < r:
        if l & 1: res = min(res, t[l]); l += 1
        if r & 1: r -= 1; res = min(res, t[r])
        l //= 2; r //= 2
    return res

Invariant: every internal node equals the combine of its two children (plus its lazy tag, if any). Updates restore it along one root-to-leaf path.

A thinking trace: count of smaller numbers after self

  1. Brute force: for each i scan the right side: O(n²), 4 × 10⁸ for n = 2 × 10⁴. Too slow in Python, borderline in C++.
  2. Reframe the direction: scan from the right. Then "elements after i" = "elements already inserted", and the question becomes how many inserted values are < x?: a prefix count over values.
  3. Structure: a Fenwick tree indexed by value: insert = add(value, 1), query = prefix(value − 1).
  4. Values up to 10⁹: compress them to ranks 1..m first. Equal values get the same rank, so "strictly smaller" is prefix(rank − 1).
  5. Alternative: merge sort, counting how many elements from the right half jump ahead of each left element. Same O(n log n), and a good second answer.

The move: turn "how many before me satisfy P" into a running structure keyed by the thing P compares. Inversions, ranks in a stream, "count pairs with a[i] > 2·a[j]" all follow.

Traps and variations

  • Fenwick is 1-indexed: i = 0 loops forever (0 & −0 = 0). Shift indices by one.
  • Point update as a delta: "set a[i] = v" needs the old value: add(i, v − a[i]).
  • Range add with point query: a BIT over the difference array. Range add with range sum: two BITs.
  • Recursion in Python segment trees is slow; prefer the iterative bottom-up form unless you need lazy propagation.
  • Sizes: a recursive segment tree needs 4n nodes; the iterative one 2·(next power of two).
  • Do you need a tree at all? Static ranges use prefix sums; offline queries can sometimes be sorted and answered with a sweep (Mo's algorithm, or sorting queries by right endpoint).
  • Interview reality: segment trees appear more at quant firms and in online assessments than in big-tech on-sites. Be able to write a BIT from memory in 2 minutes.
