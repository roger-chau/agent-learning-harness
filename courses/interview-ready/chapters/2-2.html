The signal

"For each element, find the next (or previous) greater (or smaller) element" and anything reducible to it: days until warmer, stock spans, the largest rectangle under a histogram, trapped water, sums over subarray minima. The brute force scans forward from each element, O(n²). A monotonic stack does all of them in one O(n) pass.

The core idea

Keep a stack of indices still waiting for their answer. If you're looking for the next greater element, the waiting values are non-increasing from bottom to top: a larger value would already have answered everything smaller beneath it. When a new element arrives, it is the answer for every waiting element smaller than it, which sit together at the top: pop them, record the answer, then push the new element.

The O(n) proof is amortised: every index is pushed once and popped at most once, however long any single while loop runs.

The invariant and template

st = []                       # invariant: indices awaiting an answer, values monotone bottom→top
for i, x in enumerate(a):
    while st and a[st[-1]] < x:   # x answers everything smaller on top
        j = st.pop(); answer[j] = i   # or x, or i − j, …
    st.append(i)
# indices still on the stack have no answer

Four variants differ only in the comparison and direction: next greater (pop on <), next smaller (pop on >), previous ones (read the answer from the stack top after popping, before pushing), and ties (< versus <= decides whether equal elements answer each other).

A thinking trace: sum of subarray minimums

  1. Brute force: every subarray, its minimum: O(n²) with a running min. Too slow for n = 3 × 10⁴ in Python, and the classic follow-up asks for O(n).
  2. Change the question (Chapter 0.3's meta-move): instead of "what is each subarray's minimum?", ask "for how many subarrays is a[i] the minimum?" and sum a[i] × count.
  3. Count: a[i] is the minimum of subarrays that start after the previous smaller element and end before the next smaller one: left[i] × right[i] choices.
  4. Ties: with equal values, a subarray would be counted for both. Use "previous strictly smaller" on one side and "next smaller or equal" on the other, so each subarray's minimum is attributed to exactly one index.
  5. Both distances come from monotonic-stack passes: O(n).

The contribution technique, plus the next/previous-smaller primitive, solves a family of "sum over all subarrays" problems.

Traps and variations

  • Store indices, not values: you usually need distances, and values are recoverable.
  • Sentinels simplify endings: append a 0 to a histogram so every bar gets popped; walk a circular array twice.
  • Largest rectangle is the template with a twist: a popped bar's rectangle spans from its recorded start to the current index, and the new bar inherits the leftmost popped start.
  • Monotonic deque (Chapter 1.4) is the same idea when elements also expire from the front.
