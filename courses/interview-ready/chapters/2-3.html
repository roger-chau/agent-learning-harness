The signal

Sorted data (or data sorted in pieces: rotated arrays, matrices sorted row by row), and a question about where something is or would be. More generally: any monotone predicate over indices, false…false true…true, where you want the boundary. That's O(log n) instead of O(n).

The core idea: one template, no off-by-one errors

Binary search is famous for being easy to get subtly wrong. The cure is to never write it from scratch: always find the first index where a monotone predicate is true, with a half-open range and an explicit invariant:

lo, hi = 0, n                 # invariant: answer ∈ [lo, hi]; everything < lo is false, everything ≥ hi is true
while lo < hi:
    mid = (lo + hi) // 2      # lo ≤ mid < hi
    if pred(mid): hi = mid    # mid might be the answer
    else: lo = mid + 1        # mid is false, so the answer is after it
return lo                     # n if the predicate is never true

Every binary-search question becomes: what's the predicate? "First index with a[i] ≥ x" (lower bound), "first with a[i] > x" (upper bound; count of x = upper − lower), "first index ≤ the last element" (minimum of a rotated array), "first day the condition holds".

Add one block: disguised sorted arrays

  • Rotated arrays: one half of [lo, hi] is always sorted; decide whether the target lies in it.
  • Matrices sorted row-major: a virtual array, index k at (k // cols, k % cols). Matrices sorted by rows and columns separately (but not row-major): start at the top-right corner and step left or down: O(r + c), a "staircase" search.
  • Peak finding: the predicate a[i] > a[i + 1] isn't monotone globally, but it tells you which side has a peak, which is enough.
  • Infinite or unknown size: double the bound until the predicate is true, then binary-search inside (exponential search).

A thinking trace: minimum of a rotated array

  1. Example: [4, 5, 6, 7, 0, 1, 2]. The minimum is where the order "breaks".
  2. Find a predicate: compare each element with the last one, 2: [F, F, F, F, T, T, T] for "a[i] ≤ a[n−1]". It's monotone, and its first true is the minimum. (Comparing with the first element fails when the array isn't rotated at all: check that case.)
  3. Apply the template, with pred(mid) = a[mid] ≤ a[n − 1] (equivalently a[mid] ≤ a[hi] inside the loop).
  4. Tests: not rotated, rotated by one, two elements, one element.

The skill being trained: turn the question into a monotone predicate; the template does the rest.

Traps and variations

  • Overflow in C++/Java: mid = lo + (hi − lo) / 2.
  • Infinite loops come from lo = mid with mid = (lo + hi) // 2; the template never assigns lo = mid.
  • Duplicates break the rotated-array trick (with [1, 1, 1, 0, 1] you can't tell which half is sorted): the worst case becomes O(n); say so.
  • Python's bisect_left and bisect_right and C++'s lower_bound / upper_bound are this template; use them when allowed, but be able to write it.
