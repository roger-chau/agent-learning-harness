The signal

Graphs rarely arrive labelled "graph". The interview skill is modelling: noticing that something has states and moves between states. Grids (cells and their neighbours), words that differ by one letter, lock combinations, board positions, "minimum number of operations to turn X into Y": all of these are graphs. Once you've named the nodes and edges, the algorithm is usually standard:

QuestionTool
connected? how many components? flood fill?DFS or BFS (either)

The core idea: BFS visits in order of distance

BFS processes nodes in non-decreasing distance from the start, because the queue only ever holds nodes at distance d followed by nodes at distance d + 1. So the first time BFS reaches a node is along a shortest path. That one fact is the proof of every BFS shortest-path answer, and why BFS is wrong as soon as edges have different weights.

DFS goes deep first. It's the natural tool for "explore everything reachable", connectivity, cycle detection and anything that wants a recursion: backtracking and topological order.

Multi-source BFS: put every source in the queue at distance 0. That's the same as adding a virtual super-source joined to all of them, so one BFS gives every node its distance to the nearest source in O(V + E), instead of running a BFS per source.

The invariant and template

from collections import deque
def bfs(starts):
    dist = {s: 0 for s in starts}         # mark on ENQUEUE
    q = deque(starts)
    while q:
        u = q.popleft()
        for v in neighbours(u):           # grid: 4 directions + bounds check
            if v not in dist:             # implicit: generate on demand
                dist[v] = dist[u] + 1
                q.append(v)
    return dist

The invariant: dist holds every node discovered so far with its final shortest distance; the queue holds the discovered nodes not yet expanded, in order of distance. Process "len(q) nodes per round" when you need to know where one layer ends (minutes, levels, semesters).

For grids, write the neighbour loop once with a direction array, and check bounds before indexing. In Python use an explicit stack or a deque rather than recursion: a 300 × 300 grid is 90,000 cells deep in the worst case.

A thinking trace: word ladder

  1. Model: nodes are words; an edge joins words that differ in exactly one position. We want the fewest edges from begin to end, all costing 1, so BFS.
  2. Brute force on the graph: build every edge by comparing all pairs: O(N² L). With N = 5,000 words that is 25 million comparisons before the search starts.
  3. Bottleneck: building edges we may never use.
  4. Transformation: make the graph implicit. Generate a word's neighbours when you pop it, by trying all 26 letters at each position and keeping those in a hash set. That's O(26 L) per word, so O(N · 26 · L) overall.
  5. Further: bidirectional BFS from both ends, always expanding the smaller frontier. With branching factor b and distance d, that's about 2·bd/2 nodes instead of bd.
  6. Test: end not in the list (0), begin equal to end, and an unreachable end.

The move to remember: "generate neighbours on demand" makes huge or infinite state spaces searchable. It's how you solve open-the-lock, the sliding puzzle and minimum genetic mutation.

Traps and variations

  • Mark on enqueue, not on dequeue, or a node can enter the queue many times. It stays correct, but can be far slower.
  • State must include everything that matters. With "you may break at most k walls", the state is (row, col, walls used), not (row, col). Getting the state right is the hard part of most "BFS with a twist" problems.
  • Mutating the input (setting visited cells to '0') saves memory, but ask first, or restore it afterwards.
  • Bipartite check: BFS or DFS 2-colouring; an edge between two same-coloured nodes means an odd cycle.
  • Clone a graph: BFS or DFS with a map from old node to new node, the same idea as copying a list with random pointers.
  • Pacific–Atlantic and surrounded regions: search from the border inward instead of from every cell outward. Reversing the direction of the search is a common transformation.
