The signal

"How many ways…", "count the arrangements…", an answer "modulo 10⁹+7", or a DP whose table would be astronomically large (a 10⁵ × 10⁵ grid, n up to 10¹⁸). Also any time the first few answers form a sequence you recognise. Combinatorics replaces enumeration and often replaces DP: a formula is O(1) per query.

The core idea: count structures, not sequences of steps

The toolbox, with the problems each one cracks:

Binomial coefficientC(n, k) = n! / (k!(n − k)!)lattice paths, choosing positions, subsets of size k

Modular arithmetic: + − × commute with mod. Division doesn't: divide by multiplying by the modular inverse. For a prime p, Fermat gives a⁻¹ = a^(p−2) mod p. Precompute factorials and inverse factorials once, and every C(n, k) is O(1).

The invariant and template

M = 10**9 + 7
fact = [1] * (N + 1)
for i in range(1, N + 1): fact[i] = fact[i - 1] * i % M
inv_fact = [1] * (N + 1)
inv_fact[N] = pow(fact[N], M - 2, M)              # Fermat inverse
for i in range(N, 0, -1): inv_fact[i - 1] = inv_fact[i] * i % M
def C(n, k):
    return 0 if k < 0 or k > n else fact[n] * inv_fact[k] % M * inv_fact[n - k] % M

Habits: reduce after every multiplication (in C++, 64-bit products of two values below 10⁹+7 fit, but sums of several products may not). Write the formula in words first ("choose which r of the m + n − 2 moves go down"), and check it on a tiny case by brute force before trusting it.

A thinking trace: lattice paths around a few blocks

  1. Part 6 answer: the grid DP, O(mn). With m = n = 10⁵ that's 10¹⁰ cells. Impossible.
  2. No blocks: a path is a sequence of (m − 1) downs and (n − 1) rights; choose the positions of the downs: C(m + n − 2, m − 1). O(1) after precomputation.
  3. One block B: complement. All paths − paths through B = C(to B) · C(B to end).
  4. Several blocks: subtracting each block's paths double-subtracts paths through two blocks. Organise by the first block a path hits. Sort the blocks; ways[i] = C(start → bᵢ) − Σ over earlier blocks j of ways[j] · C(bⱼ → bᵢ). Treat the target as a final block.
  5. Cost: O(k²) for k blocks, plus the factorial table. Independent of the grid area.
  6. Check: against the Part 6 DP on small random grids. (The judge's reference was verified exactly this way.)

The move: when a DP table is too big but the obstacles are few, count freely and subtract by the first bad event. This "first bad event" decomposition also counts derangements and walks avoiding a boundary (the reflection principle).

Traps and variations

  • Dividing mod p with / is wrong: use inverses. Fermat needs p prime and a not ≡ 0.
  • Overcounting by symmetry: are the items or bins distinguishable? "Distribute 5 identical balls into 3 distinct boxes" (stars and bars: 21) is different from distinct balls (3⁵ = 243).
  • Sequences you should recognise: Catalan 1, 1, 2, 5, 14, 42; Fibonacci; Bell numbers 1, 1, 2, 5, 15, 52 (set partitions); derangements 1, 0, 1, 2, 9, 44.
  • Count sorted vowel strings of length n: stars and bars, C(n + 4, 4).
  • Derangements: D(n) = (n − 1)(D(n − 1) + D(n − 2)), and D(n)/n! → 1/e. A quant favourite.
  • The reflection principle: paths from (0, 0) to (n, n) that never cross the diagonal number C(2n, n) − C(2n, n + 1), which is Catalan again.
  • Big exact numbers in Python (math.comb) are fine for n in the thousands. Use the modular version when the problem says mod.
