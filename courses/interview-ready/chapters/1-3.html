The signal

Two pointers work when the input is sorted (or can be sorted without losing what you need), or when the answer involves the two ends of something: pairs with a target sum, palindromes, partitioning, merging sorted lists, removing duplicates in place. The brute force checks all O(n²) pairs; two pointers check O(n) of them by proving that each step discards a candidate that can't be part of a better answer.

The core idea

Start with pointers at both ends (or both at the start, moving at different speeds). At each step, compare and move the pointer whose current element can't possibly be in a better answer. In sorted two-sum: if a[i] + a[j] is too small, then a[i] paired with any element left of j is even smaller, so i is useless: discard it (i += 1). Too big: discard j. Each step eliminates a whole row or column of the pair matrix, so n steps cover all n² pairs.

The invariant and template

i, j = 0, len(a) - 1
# invariant: every pair with a pointer outside [i, j] has been ruled out (or recorded)
while i < j:
    s = a[i] + a[j]
    if s < target: i += 1       # a[i] + anything ≤ a[j] is too small
    elif s > target: j -= 1     # a[j] + anything ≥ a[i] is too big
    else: record; i += 1; j -= 1 (skipping duplicates if needed)

The justification of each move is an exchange argument: show the discarded element can't beat what you'll still consider. Getting into the habit of stating it for each pointer move is what separates a guessed two-pointer solution from a correct one.

A thinking trace: container with most water

  1. Brute force: all pairs, area = (j − i) × min(h[i], h[j]): O(n²).
  2. Examples: [1, 8, 6, 2, 5, 4, 8, 3, 7] → 49 (lines 8 and 7, width 7).
  3. Bottleneck: most pairs are clearly bad. Which can we discard? Start with the widest pair (0, n − 1).
  4. Exchange argument: suppose h[i] ≤ h[j]. Any pair (i, j') with j' < j is narrower, and its height is still at most h[i]. So no pair using i can beat the current one: discard i. Symmetric if h[j] is shorter.
  5. Complexity: each step discards one index: O(n), O(1) space.
  6. Test: equal heights (either move is fine), two lines, strictly increasing heights.

The pattern of thought: "which candidate can I prove useless?" rather than "which is best?".

Traps and variations

  • Duplicates (3Sum): after a match, skip equal values on both sides, and skip equal values for the fixed element too.
  • Sorting destroys indices: if the answer needs original positions, sort (value, index) pairs, or use a hash map instead.
  • Same-direction pointers (fast and slow): removing duplicates in place, partitioning (Dutch national flag), linked-list cycle detection. The invariant is "everything before slow is the finished output".
  • Trapping rain water combines two pointers with running maxima: the side with the lower wall is decided by its own maximum, so it can be finalised and moved.
Maths shortcut. The number of pairs i < j is n(n − 1)/2, and the number of triples is C(n, 3). Say these numbers when you justify why the brute force is too slow.
