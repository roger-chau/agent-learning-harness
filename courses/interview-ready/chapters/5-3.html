The signal

Inputs are ranges [start, end]: meetings, bookings, trips, ranges of a number line, letter spans. The questions are: merge them, insert one, find the maximum overlap, choose the most non-overlapping ones, or check a capacity. Almost always the first move is to sort, by start or by end, and the choice between them is the actual decision.

The core idea: sort, then only the last one matters

After sorting by start, a new interval can overlap only the most recent merged interval. Anything earlier ended before that one began, or was merged into it. That turns merging into one linear sweep.

For counting overlaps, turn intervals into events: +1 at each start and −1 at each end. Sort the events, and the running sum is the number of active intervals at any moment. With small integer coordinates, a difference array does the same in O(n + range). The maximum of the running sum answers "how many rooms", "is capacity ever exceeded" and "the busiest time".

For selecting non-overlapping intervals, sort by end. The interval that finishes first leaves the most room for everything else.

The invariant and template

# Merge (sort by start). Invariant: out is disjoint; only out[-1] can touch what's left.
out = []
for s, e in sorted(iv):
    if out and s <= out[-1][1]: out[-1][1] = max(out[-1][1], e)
    else: out.append([s, e])

# Sweep (events). Ends before starts at equal times, for half-open intervals.
ev = sorted([(s, +1) for s, _ in iv] + [(e, -1) for _, e in iv])
cur = best = 0
for _, d in ev:
    cur += d; best = max(best, cur)

# Select the most non-overlapping (sort by end).
end, keep = -inf, 0
for s, e in sorted(iv, key=lambda x: x[1]):
    if s >= end: keep += 1; end = e

A thinking trace: non-overlapping intervals

  1. Reframe: "remove the fewest" is the same as "keep the most". Complements often turn awkward objectives into standard ones.
  2. Brute force: try all subsets, O(2ⁿ). Or DP after sorting, O(n²). Both are correct; is there a greedy?
  3. Propose greedy candidates, then attack them:
    • Earliest start first? [1, 100], [2, 3], [4, 5]: it picks [1, 100] and keeps 1, but 2 is possible. ✗
    • Shortest first? [1, 5], [4, 7], [6, 10]: it picks [4, 7] and keeps 1, but 2 is possible. ✗
    • Earliest end first? No counterexample comes to mind, so try to prove it.
  4. Exchange argument: take any optimal selection O and its first interval o₁. Let g₁ be the interval with the earliest end. Since end(g₁) ≤ end(o₁), replacing o₁ with g₁ conflicts with nothing else in O. So some optimal solution starts with g₁. Remove g₁ and everything overlapping it, and repeat. Induction finishes the proof.
  5. Code it: sort by end, keep greedily, and the answer is n − kept. O(n log n).

This is the core greedy workflow: list candidate rules, break the wrong ones with tiny counterexamples, then prove the survivor with an exchange argument. Interviewers want the counterexamples as much as the answer.

Traps and variations

  • Containment: merging [1, 10] with [2, 3] must keep end 10, so use max(), not the new end.
  • Open or closed endpoints: do [1, 2] and [2, 3] overlap? Merge intervals says yes, and non-overlapping intervals says no. Read the statement, and use ≤ or < deliberately.
  • Already sorted input: insert interval should be O(n), not a re-sort.
  • Minimum arrows to burst balloons = the maximum number of non-overlapping intervals (closed endpoints). It's the same greedy.
  • Interval intersection of two sorted lists: two pointers; advance whichever interval ends first.
  • Employee free time / gaps: merge everything, then report the gaps between consecutive merged intervals.
  • Weighted interval scheduling (each interval has a value): greedy fails. Sort by end, then DP with binary search for the last compatible interval, O(n log n). That's Part 6.
