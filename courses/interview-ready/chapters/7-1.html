The signal

The input is a sequence and the operations merge, split or remove pieces, with costs that depend on the neighbours at the time: burst balloons, cut a stick, merge stones, matrix-chain multiplication, optimal BST, palindrome partitioning, "remove boxes". If the order of operations matters and greedy fails, and n is small (≤ 500 or so), think DP over intervals [i, j]: O(n²) states and O(n) transitions each, O(n³) total.

The core idea: pick the event that splits the interval

For an interval [i, j], choose one special element k so that, once you condition on it, the left and right parts no longer interact. Then dp[i][j] = best over k of dp[i][k] + dp[k][j] + cost(i, k, j).

The hard part is choosing which event to condition on:

  • Burst balloons: the first balloon burst changes its neighbours' neighbours, so the sides interact. The last balloon burst in (i, j) has neighbours exactly i and j, and it separates the sides for the whole process.
  • Cutting a stick: the first cut costs the full segment length and leaves two independent pieces.
  • Matrix chain: the last multiplication splits the product into a left and right block.

The test: after fixing k, can I solve the two sides without knowing anything about each other? If yes, you've found the decomposition.

The invariant and template

dp = [[0] * n for _ in range(n)]           # dp[i][j] over an interval (often open: (i, j))
for length in range(2, n):                 # ORDER: by increasing length
    for i in range(n - length):
        j = i + length
        dp[i][j] = best(dp[i][k] + dp[k][j] + cost(i, k, j) for k in range(i + 1, j))
return dp[0][n - 1]

Invariant: when dp[i][j] is computed, every strictly shorter interval is final. Iterating by length (not by i, then j) guarantees that. Add sentinels at both ends (1s for balloons; 0 and n for a stick) so boundary intervals need no special case. Index by the interesting points (cut positions), not every coordinate.

A thinking trace: burst balloons

  1. Brute force: try every order, n! of them.
  2. First decomposition attempt: pick the first balloon k to burst. Then the left and right parts become adjacent, so the left part's future rewards depend on the right part. Not independent. Reject.
  3. Flip it: pick the last balloon k to burst in the open interval (i, j). Until k bursts, it stands between the two sides, so they never become neighbours. When k finally bursts, everything else inside is gone, so its neighbours are exactly i and j and it earns a[i]·a[k]·a[j].
  4. Recurrence: dp[i][j] = max over k of dp[i][k] + a[i]a[k]a[j] + dp[k][j], with sentinel 1s at both ends.
  5. Order and cost: by increasing length, O(n³), which is fine for n ≤ 300.

The move: if conditioning on the first event couples the subproblems, try the last one. Thinking about time backwards is a recurring trick, as in Part 6's dungeon game.

Traps and variations

  • Wrong loop order (i then j ascending) reads intervals before they're computed. Loop by length, or i descending with j ascending.
  • Open versus closed intervals: decide whether i and j are included and stay consistent. Balloons use open intervals; palindromes use closed ones.
  • Stacked DPs: palindrome partitioning precomputes an interval table, then runs a 1-D DP over it.
  • Merge stones with k piles adds a "number of piles" dimension. Check feasibility first ((n − 1) mod (k − 1) = 0).
  • Optimisations: Knuth's optimisation (O(n²) when the optimal split is monotone) exists. Mention it; rarely required.
  • Strange printer and remove boxes: interval DP with an extra parameter for what's attached to the left end. These are among the hardest common ones.
