The signal

Union-find (disjoint-set union, DSU) answers "are x and y connected?" while edges are added over time: counting components online, detecting the edge that creates a cycle, grouping equivalent items (accounts with shared emails, equal variables, similar strings), and Kruskal's MST. If the problem merges groups and asks about membership, think DSU.

Minimum spanning trees appear as "connect everything at minimum total cost": cables, roads, points. Related problems reduce to them: the minimax path between two nodes lies on the MST, and clustering into k groups means cutting the k − 1 most expensive MST edges.

The core idea

Each set is a tree of parent pointers; its root is its name. find walks to the root; union links one root under the other. Two optimisations make each operation effectively O(1) (amortised O(α(n)), where α is the inverse Ackermann function, below 5 for any realistic n):

  • Path compression: during find, point nodes closer to the root (path halving: parent[x] = parent[parent[x]]).
  • Union by size or rank: attach the smaller tree under the larger, so depth stays O(log n) even without compression.

The limits: DSU can't split sets or delete edges, and it can't give you paths. If deletions are needed, process the operations in reverse (deletions become additions), which is a classic transformation.

The MST cut property: for any division of the nodes into two sides, the cheapest edge crossing it belongs to some MST. Kruskal takes edges in increasing weight, keeping those that join different DSU sets. Prim grows one tree, always adding its cheapest outgoing edge. Both are this property applied greedily.

The invariant and template

class DSU:
    def __init__(self, n):
        self.p = list(range(n)); self.sz = [1] * n; self.count = n
    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]   # path halving
            x = self.p[x]
        return x
    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b: return False            # already connected: this edge closes a cycle
        if self.sz[a] < self.sz[b]: a, b = b, a
        self.p[b] = a; self.sz[a] += self.sz[b]; self.count -= 1
        return True

The invariant: two nodes are in the same set exactly when the edges processed so far connect them. union returning False is the cycle detector.

A thinking trace: satisfiability of equality equations

  1. Model: variables are nodes, and "a==b" is an edge. Equality is transitive, so the variables forced equal are exactly the connected components.
  2. The tempting mistake: processing equations in the given order, checking each "!=" as it arrives. ["a!=c", "a==b", "b==c"] passes the "!=" check before a and c are merged.
  3. Fix the order: all equalities first (build the components), then all inequalities (each must cross components). Two passes, O(n α).
  4. Why DSU and not DFS? Either works here. DSU is shorter, and it stays correct if equations stream in and you must answer after each one (then ask the follow-up: what if an inequality arrives before its contradicting equalities? Keep the inequalities and re-check them on each union).
  5. Test: "a!=a" (false), "a==a" (true), and variables that appear only in inequalities.

The transferable move: when constraints have different kinds, ask what order to process them in. Building before checking, or reversing time to turn deletions into additions, often turns a hard problem into a simple one.

Traps and variations

  • Recursive find in Python on a long chain overflows the stack before compression kicks in. Use the iterative version.
  • Union of roots, not nodes: p[a] = b on non-roots corrupts the structure.
  • Mapping keys to indices: for strings (emails, names) keep a dict from key to int, or use a dict-based DSU.
  • Accounts merge: union every email with the account's first email; group by root; sort each group.
  • Number of islands II (land added cell by cell, report islands after each): DSU over cells, the online version of flood fill.
  • Kruskal versus Prim: Kruskal is O(E log E), best for sparse edge lists. Array Prim is O(V²), best for dense or implicit complete graphs such as points in the plane.
  • Weighted DSU (each node stores its ratio or offset to its parent) answers "a / b = ?" style queries. Evaluate-division is the standard example.
