And a binary search tree appears whenever you need ordered data with O(h) search, insert, floor and ceiling. In practice that means std::set or std::map in C++, and sortedcontainers or bisect on a list in Python.

The core idea: the BST property is a range

The BST invariant is not "left child < node < right child". It is: every value in the left subtree is less than the node, and every value in the right subtree is greater. Equivalently, each node lives in an open interval inherited from its ancestors, and an in-order traversal is strictly increasing.

That one sentence gives you validation (pass bounds down), search and insertion (go left or right, O(h)), k-th smallest (in-order, stop at k), the LCA in a BST (the first node whose value lies between p and q), and the inorder successor (the leftmost node of the right subtree, else the last ancestor where you went left).

The invariant and template

# BFS by levels: a round takes exactly the nodes present at its start.
q = deque([root])
while q:
    for _ in range(len(q)):
        n = q.popleft()
        ...                       # the level's nodes, left to right
        if n.left: q.append(n.left)
        if n.right: q.append(n.right)

# Iterative in-order. Invariant: the stack holds the ancestors still to visit.
st, n = [], root
while st or n:
    while n:
        st.append(n); n = n.left   # push the left spine
    n = st.pop()
    visit(n)
    n = n.right

LCA in a general binary tree: f(node) returns the p or q node found in this subtree, or None. If both children return something, this node is the split point. Otherwise pass up whichever side found something. One post-order pass, O(n).

Serialisation: pre-order with explicit null markers ("1,2,#,#,3,#,#") is unambiguous and rebuilds with one recursive reader. In-order alone is ambiguous, but pre-order plus in-order (with distinct values) determines the tree: the first pre-order value is the root, and its position in the in-order splits the two subtrees.

A thinking trace: validate a BST

  1. First idea: check that left.val < node.val < right.val at every node.
  2. Attack your own idea. Before coding, look for a counterexample: [5, 4, 6, null, null, 3, 7]. Every parent/child pair is fine, but 3 sits in 5's right subtree. The local check fails.
  3. Diagnose: the constraint on a node comes from all its ancestors, not just its parent. Information has to flow top-down.
  4. Transformation: pass an interval (low, high). The left child inherits (low, val) and the right child (val, high). Each node does an O(1) check, O(n) in total.
  5. Alternative proof route: the in-order sequence must be strictly increasing. Track the previous value during the traversal.
  6. Test: duplicates ([1, 1] is invalid when the property is strict), values at INT_MIN and INT_MAX (so use 64-bit or None for the bounds), and the empty tree (valid).

The transferable move is step 2: try to break your first idea with a small adversarial example before writing code. Interviewers notice it, and it saves you from debugging a wrong algorithm.

Traps and variations

  • "Balanced" is not given. O(h) is O(n) on a degenerate BST. Say so when quoting complexity.
  • LCA: BST or general tree? Ask. A BST allows the O(h) walk; a general tree needs the post-order search.
  • Zigzag order: BFS plus reversing alternate levels (or appending to the front of a deque). Don't build two stacks unless asked.
  • Vertical order: BFS carrying a column index, then sort by (column, row, value).
  • Construct from pre-order and in-order: a hash map from value to in-order index gives O(n); slicing lists gives O(n²).
  • The k-th smallest with frequent updates: augment the nodes with subtree sizes (an order-statistic tree), giving O(h) per query.
  • Morris traversal: O(1)-space in-order that temporarily threads right pointers. Know that it exists; rarely required.
