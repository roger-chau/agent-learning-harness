The signal

A shortest or cheapest path where edges have different costs. Pick the tool by what the weights look like and what constraints sit on the path:

Weights / constraintAlgorithmCost
all equalBFSO(V + E)
0 or 10-1 BFS (deque)O(V + E)
non-negativeDijkstra (binary heap)O(E log V)
negative edges, or "at most k edges"Bellman–Ford (k rounds)O(kE)

The core idea: settle the closest node

Dijkstra generalises BFS. Always expand the unsettled node with the smallest tentative distance. With non-negative weights that distance is final: any other route to it would leave the settled region through a node at least as far away, then add non-negative edges.

That proof tells you exactly when Dijkstra applies: any path cost that never decreases when you extend the path. Sums of non-negative weights qualify, and so does the maximum edge on the path (minimum effort), or a product of probabilities ≤ 1 (maximise it by running on −log). Negative edges break the proof, and so does a constraint like "at most k stops" that makes a costlier-but-shorter partial path worth keeping.

When the constraint breaks it, enlarge the state: run Dijkstra on (node, stops used), or use Bellman–Ford, whose round i computes the best cost using at most i edges.

The invariant and template

import heapq
def dijkstra(g, s):                   # g[u] = [(v, w), ...], w >= 0
    dist = {s: 0}; h = [(0, s)]
    while h:
        d, u = heapq.heappop(h)
        if d > dist[u]: continue      # stale entry: lazy deletion
        for v, w in g[u]:
            nd = d + w
            if nd < dist.get(v, float('inf')):
                dist[v] = nd; heapq.heappush(h, (nd, v))
    return dist

# 0-1 BFS: weight-0 moves to the FRONT, weight-1 moves to the BACK
# Bellman–Ford with at most k edges: k rounds, each relaxing from a COPY of the previous round

Invariant: every popped, non-stale (d, u) has d equal to the true distance of u. The heap may hold several entries per node, and lazy deletion is simpler than a decrease-key operation, costing O(E log E) = O(E log V).

A thinking trace: cheapest flights within k stops

  1. Clarify: k stops means at most k + 1 flights. Prices are positive. The graph is directed.
  2. First idea: Dijkstra on price. Attack it: A→D directly costs 500; A→B→C→D costs 300, but k = 1 allows only 2 flights. Dijkstra settles D at 300 via a route that is too long, and may already have discarded the 500 route. The constraint breaks the "settled is final" proof.
  3. Diagnose: the state "at city v" is not enough; "at city v having used i flights" is.
  4. Option A: Bellman–Ford, which has exactly that structure. After round i, d[v] is the cheapest price using ≤ i flights. Run k + 1 rounds, relaxing from the previous round's array. Relaxing in place could chain two flights in one round. O(k · E).
  5. Option B: Dijkstra on (cost, city, flights). Prune a state if this city was already reached with fewer flights at lower cost.
  6. Test: k = 0 (direct flights only), src = dst (cost 0), and an unreachable dst.

Two lessons: re-check an algorithm's correctness proof against the problem's extra constraints, and when the proof fails, add the missing information to the state.

Traps and variations

  • The copy in Bellman–Ford when edges are bounded (above).
  • Overflow: INT_MAX + w wraps in C++. Use long long, or INF = 1e18, or check d != INF before relaxing.
  • Early exit: with a single target, return when the target is popped, not when it's first pushed.
  • Dense graphs: with E ≈ V², array Dijkstra (no heap) is O(V²) and beats the heap version.
  • Path reconstruction: keep a parent pointer on each relaxation.
  • Negative cycles: Bellman–Ford detects them with one extra round. Currency arbitrage, a quant favourite, is "is there a negative cycle in −log(rates)?"
  • Swim in rising water, minimum effort path: minimax paths, solvable three ways (Dijkstra with max, binary search plus BFS, or Kruskal with union-find). Say all three.
