The signal

Any binary-tree question whose answer can be assembled from answers about the two subtrees: depth, size, balance, diameter, path sums, whether two trees are equal or mirrored, the subtree with the largest sum. If you can phrase it as "the answer for a node is a function of the answers for its children", it is a post-order recursion and runs in O(n).

The core idea: the recursive contract

Don't trace recursion in your head; it doesn't scale and it wastes interview minutes. Instead write the contract in one sentence: "f(node) returns ___ for the subtree rooted at node." Then:

  1. Base case: what does f(None) return? (0, True, −∞, an empty list…)
  2. Leap of faith: assume f(node.left) and f(node.right) honour the contract.
  3. Combine: build f(node) from those two answers and node.val.

Two directions of information flow:

  • Bottom-up (return values): children summarise themselves to the parent: heights, sums, "found p".
  • Top-down (parameters): the parent passes constraints down: depth so far, the valid (low, high) range for a BST, the path sum so far.

Many problems use both. Deciding which information flows which way is the design step.

The invariant and template: return one thing, record another

def solve(root):
    best = initial
    def f(node):                 # contract: returns what the PARENT needs
        nonlocal best
        if node is None:
            return base
        l, r = f(node.left), f(node.right)
        best = max(best, combine_through(node, l, r))   # what the QUESTION asks
        return extend_upward(node, l, r)
    f(root)
    return best

This is the most important tree pattern in interviews. The quantity a parent can use is often different from the quantity the question asks for:

  • Diameter: return the height; record left + right.
  • Max path sum: return the best downward path, max(l, r) + val; record val + l + r.
  • Balanced? Return the height, or −1 as a "not balanced" sentinel. This avoids the O(n²) solution that recomputes heights at every node.
  • Longest univalue path, binary tree cameras, house robber III: the same shape, sometimes returning a tuple of states.

A thinking trace: maximum path sum

  1. Clarify: a path is any connected sequence, not necessarily through the root, and it is non-empty. Values can be negative, so the answer can be negative (a single node −3).
  2. Brute force: every pair of endpoints, then walk the path: O(n²) or worse.
  3. Structure: every path has a unique highest node where it "bends". So the answer is the maximum over all nodes of the best path bending there.
  4. What does the parent need? A path bending at the parent can extend into this subtree only as a straight downward chain. So the contract is: f(node) = the best downward path sum starting at node.
  5. Negatives: a branch with a negative gain is worse than no branch, so clamp: l = max(f(left), 0).
  6. Record: best = max(best, val + l + r). Return: val + max(l, r).
  7. Test: [−3] gives −3, so best must start at −∞, not 0. [2, −1] gives 2.

Notice the moves: find the canonical point (the bend), then split "what I return" from "what I record". Both recur constantly.

Traps and variations

  • Null versus leaf: "root-to-leaf path sum" must check that both children are None; a node with one child is not a leaf. Minimum depth is the classic bug.
  • Recursion depth: a degenerate tree of 10⁵ nodes overflows Python's default limit of about 1,000. Mention sys.setrecursionlimit or an explicit stack; in C++ the default stack handles around 10⁵ frames, but not 10⁷.
  • Global state in C++: reset member or global accumulators at the start of each call; the judge may call your function many times.
  • O(n²) by recomputing: calling height() inside a recursion over all nodes. Return the height instead.
  • Two trees at once: same tree, symmetric tree and subtree-of all recurse on pairs (a, b). Symmetric compares (a.left, b.right) and (a.right, b.left).
  • Path sum III (paths downward from anywhere summing to k): prefix sums along the root-to-node path, with a hash map you add to on entry and remove from on exit. This is Part 1's prefix-sum trick on a tree.
