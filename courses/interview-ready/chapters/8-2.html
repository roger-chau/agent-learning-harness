The signal

String problems where the naive approach compares substrings repeatedly: find a pattern (or many), periodicity ("is s a repetition of a smaller string?"), the longest prefix that is also a suffix, palindromic prefixes, the longest repeated or common substring, counting distinct substrings. When n reaches 10⁵ and the naive cost is O(n·m) or O(n²·L), you need a linear-time string tool.

The core idea: reuse what you've already matched

Prefix function (KMP): pi[i] = the length of the longest proper prefix of s[:i+1] that is also a suffix of it (its longest border). On a mismatch after matching k characters, jump to k = pi[k − 1] instead of restarting. You never re-read text characters, so matching costs O(n + m).

Z-function: z[i] = the length of the longest common prefix of s and s[i:]. It's the same information, organised differently, and computed in O(n) with a moving window [l, r).

Rolling hash (Rabin–Karp): hash every length-L window in O(1) each by sliding: h' = (h − c_out·Bᴸ⁻¹)·B + c_in. Equality of substrings becomes equality of numbers (modulo collisions), and pairs with binary search over L for "longest repeated substring".

The concatenation trick: run the prefix function or Z-function on pattern + '#' + text or s + '#' + reverse(s). The separator stops matches crossing the boundary, and the answer becomes a value in the array.

The invariant and template

def prefix_function(s):
    pi = [0] * len(s); k = 0                 # invariant: k = pi[i - 1] at the top of each iteration
    for i in range(1, len(s)):
        while k and s[i] != s[k]: k = pi[k - 1]   # fall back to the next shorter border
        if s[i] == s[k]: k += 1
        pi[i] = k
    return pi

# Rolling hash of all windows of length L
h = 0; p = pow(B, L, M)
for i, c in enumerate(s):
    h = (h * B + ord(c)) % M
    if i >= L: h = (h - ord(s[i - L]) * p) % M
    if i >= L - 1: use(h, i - L + 1)

Period of a string: the smallest period is n − pi[n − 1]; s is a repetition of a smaller block iff that period divides n (and is less than n).

A thinking trace: shortest palindrome

  1. Restate: add characters only to the front. If s = P + rest where P is a palindrome, the answer is reverse(rest) + s. So maximise the palindromic prefix P.
  2. Brute force: test each prefix for being a palindrome, longest first: O(n²). For "aaaa…ab…" inputs that's the worst case, 10⁹ at n = 4 × 10⁴.
  3. Translate the condition: P is a palindrome ⇔ P = reverse(P) ⇔ P (a prefix of s) equals a suffix of reverse(s).
  4. "A prefix equal to a suffix" is a border. Compute the prefix function of t = s + '#' + reverse(s); pi[last] is the longest prefix of s that is also a suffix of reverse(s), which is exactly |P|. The '#' stops it exceeding |s|.
  5. Answer: reverse(s[pi[-1]:]) + s. O(n).

The move: rewrite the condition until it matches the definition of a tool you know, here "prefix that is also a suffix" = border = prefix function.

Traps and variations

  • Hash collisions: with a 32-bit modulus and 10⁵ windows, the birthday bound makes collisions likely. Use a 61-bit Mersenne modulus or two moduli, and verify on equal hashes when correctness matters. Adversarial tests can target overflowing 64-bit hashing with a fixed base, so randomise the base.
  • Python's built-ins (in, find) are fast C loops; use them in practice and say so, but know the algorithm.
  • Repeated substring pattern: s is a repetition iff s is found in (s + s)[1:−1], or via the period from pi.
  • Many patterns: Aho–Corasick is KMP on a trie (Part 3's Word Search II with failure links). Know that it exists.
  • Longest palindromic substring: expand around centres in O(n²) is the expected answer; Manacher's algorithm is O(n).
  • Suffix arrays and automata solve distinct substrings and longest common substring in O(n log n) or O(n). They're rare in interviews but common at quant online assessments with string-heavy problems.
