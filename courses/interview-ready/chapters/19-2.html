The signal

"Build OHLC bars from trades", "maintain the top of book from level-2 updates", "compute VWAP over the last N minutes", "rolling z-score of the spread". These are the take-home and on-site tasks of quant-dev interviews, and the daily work of the role. They're graded on correctness in edge cases, clean streaming design, and numerical care.

The core idea: streaming state machines

Every market-data task is a fold over an ordered stream: keep a small state, update it per message, emit results. Choose the state so each update is O(1) or O(log n):

TaskStatePer-update cost
OHLC barsthe open barO(1)
VWAP over a time windowdeque of (t, p·q, q) + running sumsamortised O(1)
Rolling mean/variancewindow + stable running momentsO(1)
Rolling max/minmonotonic deque (Part 1.4)amortised O(1)
Top of bookprice → size maps, best trackingO(log n) or O(1) with arrays
Rolling mediantwo heaps with lazy deletion (Part 5.2)O(log w)

The numerical lesson from the judged rolling z-score: running sums of squares lose all precision when the level is large and the variance tiny. Centre on a reference value, or use Welford's update.

The invariant and template

# Time-window VWAP: invariant (pv_sum, q_sum) equal the sums over trades in (t − W, t]
from collections import deque
win, pv, qs = deque(), 0.0, 0
def on_trade(t, px, q):
    global pv, qs
    win.append((t, px * q, q)); pv += px * q; qs += q
    while win[0][0] <= t - W:
        _, a, b = win.popleft(); pv -= a; qs -= b
    return pv / qs

# Welford (insert only): stable mean and variance
n, mean, M2 = 0, 0.0, 0.0
def add(x):
    global n, mean, M2
    n += 1; d = x - mean; mean += d / n; M2 += d * (x - mean)   # variance = M2 / n

A thinking trace: top of book from L2

  1. Semantics first: does an update carry the level's new total size or a delta? (Here: the new size; 0 deletes.) Ask; getting it wrong corrupts the book silently.
  2. State: per side a map price → size. Best bid = max key, best ask = min key.
  3. Language choice: in C++, std::map with greater<> for bids gives best = begin(). In Python there's no built-in sorted map, so use a dict plus a heap with lazy deletion.
  4. Edge cases: deleting the best level (find the next), an empty side (−1), re-adding a deleted price, a crossed book from bad data (flag it).
  5. Production version: an array indexed by (price − base) in ticks, with the best index tracked and scanned only when the best level empties, giving O(1) typical updates. Recentre the base if the price drifts outside the band.

Traps and variations

  • Bar alignment: exchange timestamps vs receive timestamps; time zones and session boundaries.
  • Out-of-order trades: decide on a policy (drop, buffer, amend the closed bar) and document it.
  • VWAP with zero volume in a window: define the output (carry forward, or none).
  • Corporate actions (splits, dividends) adjust historical prices: research data needs adjusted series; live trading doesn't.
