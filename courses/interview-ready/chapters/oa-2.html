What this is

A 90-minute mock online assessment over all of Track A (Parts 1–8). Three new problems, one of which looks like a greedy problem but isn't. Take it after the Part 8 checkpoint, timed and closed-book. If you score below 70%, the review tells you which Part to revisit. Retake it no sooner than a week later: the problems will be familiar, so the point of a retake is speed and clean code.

How to run a timed assessment

Online assessments (HackerRank, CodeSignal, Codility) reward a different skill mix from on-site interviews: nobody hears your reasoning, partial credit is per hidden test, and the clock is the main opponent. A plan, used every time:

  1. Read every problem first (3–5 minutes). Note the constraints and guess each one's pattern and difficulty. Constraints are the problem setter telling you the intended complexity (Chapter 0.2's table).
  2. Solve in order of points per minute, not in the order given. Bank the easiest one completely first.
  3. Brute force is a strategy. If you're stuck, a correct O(n²) solution often passes 40–70% of the tests. Submit it, then improve it if time allows. Never leave a problem blank.
  4. Edge cases before submitting: empty or single element, all equal, maximum sizes (overflow in C++, recursion depth in Python), negative numbers, duplicates.
  5. Use the samples, then write one of your own that targets the case you're least sure of. Running samples is free; failing hidden tests isn't.
  6. Time-box: if a problem has taken 1.5× its share without progress, move on and come back.

Here, each coding problem's score is the fraction of hidden tests passed, just as on the real platforms. Run your solutions on the samples as often as you like. Hidden tests run once, when you submit.
