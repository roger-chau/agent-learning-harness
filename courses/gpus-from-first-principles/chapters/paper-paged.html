The work
W. Kwon, Z. Li, S. Zhuang, Y. Sheng, L. Zheng, C. H. Yu, J. E. Gonzalez, H. Zhang, I. Stoica. "Efficient Memory Management for Large Language Model Serving with PagedAttention." SOSP 2023.
arXiv:2309.06180 · A systems paper: read it as an operating-systems idea moved onto a GPU. It's the paper behind vLLM.

The problem

Serving an LLM, every request keeps a KV cache: the keys and values of all its tokens so far, for every layer, so each new token can attend to them. It's large: for a 13B-parameter model, the paper puts it at around 800 KB per token. And it grows token by token, to a length nobody knows in advance. Systems of the time allocated each request a contiguous chunk sized for the maximum possible length. The paper measured that most of that memory was wasted, through over-reservation and fragmentation, and that this, not compute, capped how many requests could be batched.

The key idea

Treat the KV cache like virtual memory. Split it into fixed-size blocks (pages) of, say, 16 tokens. Each request has a block table mapping its logical blocks to physical blocks anywhere in GPU memory, allocated on demand as it grows:

  • waste is limited to the unfilled part of each request's last block;
  • no external fragmentation, since any free block fits anywhere;
  • sharing: requests with a common prefix (parallel sampling, beam search, shared system prompts) point at the same physical blocks, with reference counts and copy-on-write when one of them appends to a shared, partly filled block.

The cost: attention can no longer assume a request's keys are contiguous. The PagedAttention kernel reads keys and values through the block table, a gather, which the paper shows costs little next to what the extra batch size gains.

Reading guide

  • The memory-waste analysis: where the KV cache's memory goes in earlier systems (reserved, internally and externally fragmented, actually used).
  • PagedAttention and the block table, then the copy-on-write sharing for parallel sampling and beam search.
  • Scheduling and preemption: what vLLM does when memory runs out (swap to CPU or recompute), which your Scenario 7 sidesteps with no preemption.
  • The evaluation: throughput at equal latency against the systems of the time; the gains grow with longer sequences and larger sampling widths.

Reproduce it

Size a KV cache from a model's shape, and measure the waste of contiguous reservation against paging for a mix of request lengths. The paper project then builds the paged cache itself, with copy-on-write.

What happened next

vLLM became one of the most widely used open-source serving engines, and paged KV caches and continuous batching became standard across serving systems. Follow-ups pushed further: prefix caching across requests, chunked prefill mixing prompt processing with decoding, quantised KV caches, and splitting prefill and decode onto different GPUs. The kernel side (paged, split-KV decoding attention) is FlashAttention's territory, the capstone's paper.
