The last milestone of Project A: two kernels taken to the memory roofline. You've measured everything in this Part; now hit the numbers.

Part 1: transpose, three ways

Transpose an $n \times n$ float matrix: b[x][y] = a[y][x], with $n$ a multiple of 32. Write three kernels and a launcher:

  1. transposeNaive(a, b, n): one element per thread, straight from global to global. One side is always uncoalesced.
  2. transposeTiled(a, b, n): a 32×32 tile in shared memory, without padding. Both global sides are coalesced; the shared-memory column read is a 32-way bank conflict.
  3. transposePadded(a, b, n): the same with a 32×33 tile. No conflicts.
  4. runTranspose(kind, a, b, n), where kind is "naive", "tiled" or "padded", launches the right kernel and returns the stats. For the tiled kernels, 32×8 blocks with 4 elements per thread (as in Chapter 2.5) work well.

Before you run them, predict each one's limitedBy on a 512×512 matrix. Then check your predictions: naive is limited by L2 bandwidth (wasted sectors), tiled by instruction issue (conflict passes), padded by DRAM. The padded one will say "DRAM latency": even at full occupancy the GW-1 sits just under Little's-law saturation (Chapter 2.6), so it lands around 90% of peak rather than 100%.

Part 2: a tiled horizontal blur

Your A2 horizontal blur reads each pixel 5 times from global memory. L2 catches the repeats, but L2 bandwidth becomes the limit. Write blurHTiled(src, dst, w, h):

  • each block loads its row segment plus a 2-pixel halo on each side into shared memory, once;
  • __syncthreads();
  • each thread computes its output from shared memory.

and runBlurH(src, dst, w, h) to launch it. Same clamp-to-edge borders as before. Think about block shape: the halo costs a few extra, poorly coalesced loads per row segment, so wider segments waste less.

How it's checked (on 512×512 unless noted)

  • All three transposes correct (also on 96×96). Tiled and padded transposes ≥ 99% coalescing and use shared memory.
  • transposePadded: zero bank conflicts and ≥ 80% of peak bandwidth.
  • transposeTiled has bank conflicts (it's meant to: that's the comparison).
  • blurHTiled: correct (also on 203×157), ≥ 95% coalescing, zero bank conflicts, ≥ 80% of peak bandwidth.

When you pass, print all four kernels' stats side by side. That table of coalescing, L2 hit rate, bank conflicts and % of peak is the write-up of Project A.
