Paper project · A mini tile compiler
Generate tiled, fused kernels from a description, then let a tuner pick the best one.

Build

Three functions:

  • compileMatmul(cfg) returns simulator kernel source (a string) for matmul(A, B, C, bias, n), computing C = epilogue(A · B) for n × n row-major matrices. cfg = { BM, BN, BK, TM, TN, epilogue }: the block tile, the k-step, the per-thread tile, and an epilogue, one of "none", "relu" (max(v, 0)) or "bias-relu" (max(v + bias[col], 0)), fused into the store.
  • launchConfig(cfg, n) returns the matching launch config, declaring registers honestly.
  • autotune(n, configs, A, B, C, bias) compiles each config with gpu.compile, measures it, and returns { best, results }, where results lists { cfg, cycles } per config.

This is a compiler in miniature: a description in, code out, with the tile sizes as the knobs and measurement deciding. Generating source from templates is how many real kernel generators work. Triton itself goes further, building IR and running passes, which is the Tiny Kernel Compiler course after this one.

How it's checked

  • Generated kernels are correct at n = 64 for several configurations (including 1 × 1 and 4 × 4 thread tiles) and every epilogue.
  • autotune at n = 128 over four candidates: its best has the lowest measured cycles in results, and re-running the best config reproduces its cycle count.
