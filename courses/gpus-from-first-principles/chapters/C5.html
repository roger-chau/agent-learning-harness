Project C · GEMM · Milestone 5 of 5
Beat the compiler on your GEMM's inner loop, by hand, in assembly.

The setup

The starter contains BASELINE: GWX for a register-tiled GEMM micro-kernel of the kind a straightforward compiler emits. Two warps run it; each lane computes a 4 × 4 tile of C from shared-memory tiles over 32 k-steps:

  • As[k*16 + row]: 32 k-steps × 16 rows of A, stored transposed; Bs[k*32 + col]: 32 × 32 of B.
  • Lane l owns rows (l >> 3)·4 … +3 and columns (l & 7)·4 … +3; warp w writes rows 16w … of C (32 columns, row-major).
  • The SM's register file is limited to 48 registers per thread for 2 warps (registerFile: 2 × 32 × 48).

The baseline takes about 3,000 cycles. Write FAST: the same results, in ≤ 1,900 cycles. Stretch: ≤ 1,550.

Your toolbox (Chapters 6.3–6.5)

  • Instruction selection: ld.shared.v4 {%a, %b, %c, %d}, S[...] loads 4 consecutive values (address a multiple of 4) in one instruction.
  • Strength reduction: the baseline recomputes addresses from k every iteration.
  • Unrolling and software pipelining: load step k+1's operands before step k's FMAs.
  • Register allocation: everything must fit in 48 names. You'll feel the pressure as soon as you pipeline.

How it's checked, and the write-up

Results must match the baseline exactly (same operations, same order of accumulation per element), within the register budget, under the cycle target. Then write up each transformation you applied, which compiler concept it is, what it did to instructions, stalls and registers, and which ones a real compiler would have done for you, and why it might not have.
