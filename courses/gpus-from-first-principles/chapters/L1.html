Why this lab

Part 1 built the SIMT model on the simulator: a warp issues one instruction for 32 lanes, a branch that splits a warp runs both sides one after the other, and a branch that's uniform within each warp costs nothing extra. Hardware is allowed to be cleverer than a model. Here you find out how closely your Turing GPU follows it, and you write the first two Project A kernels for real.

What to do

Open labs/L1-warps/l1.cu and implement the TODO kernels.

  • A. Grayscale. Interleaved 8-bit RGB in, one gray byte out, using the integer weights in the file so the result is exact. Start with one pixel per thread. It's memory-bound: each pixel is 4 bytes of traffic.
  • B. Divergence. Four kernels doing the same 4,096 dependent FMAs per thread: uniform (everyone takes path A), divergent (odd lanes A, even lanes B), warp_aligned (odd warps A, even warps B) and branch_free (the same results as divergent, by selecting the constants first and running one loop).
  • C. Blur. A 3 × 3 box blur with clamp-to-edge borders on a 4093 × 2311 float image (awkward sizes on purpose). Map threadIdx.x to x.

Predict first, in the write-up: the divergent/uniform time ratio, the warp-aligned/uniform ratio, and the branch-free/uniform ratio. Then make run.

Going further

  • Read the machine code. make sass, then find the divergent kernel. Look for the branch (BRA) and the reconvergence instructions (on Volta and later, BSSY/BSYNC), and compare with branch_free. Chapter 1.4's reconvergence model is now in front of you.
  • Profile. make ncu, and in the divergent kernel's report find "Warp Execution Efficiency" or the average active threads per warp (the exact name varies with the Nsight Compute version). It should be close to 50%.
  • Grayscale faster. One pixel per thread means 3 separate byte loads per thread. Try 4 pixels per thread using three 4-byte loads (12 bytes = 4 RGB pixels), and measure again.

What the numbers mean

If divergent takes about twice as long as uniform, the hardware is serialising the two paths exactly as the SIMT model says. If warp_aligned costs about the same as uniform, divergence is a per-warp effect, not a per-branch one: the cure is to arrange data so that threads in a warp agree. branch_free shows the other cure: turn a difference in code into a difference in data.

For the blur, the effective bandwidth counts each input pixel once even though each is read 9 times; caches serve the repeats. Comparing it with Lab 0's copy bandwidth tells you how well they do.

Passing

All three parts correct; divergence costs at least 1.6×; warp-aligned and branch-free within 15% of uniform; grayscale at least 50% and blur at least 45% of peak bandwidth (both effective). The targets are deliberately conservative, since cards and drivers vary: record what you actually get.
