The real problem

Each thread runs its own code, so each thread may take its own path through an if. But a warp issues one instruction at a time for all its lanes. What happens when lanes 0–15 want the then branch and lanes 16–31 want the else?

The smallest idea

The warp executes both paths, one after the other, with lanes masked off. The hardware keeps an active mask, one bit per lane. At a branch where lanes disagree, which is called divergence, the warp runs the then path with only the "true" lanes active, then the else path with only the "false" lanes active. At the point where both paths meet again, the reconvergence point, the full mask is restored.

Step through it. Lines 3–4 run with roughly half the lanes, line 6 with the other half. The warp issued three instructions' worth of time for the two paths, but each lane did useful work in only one or two of them. The SIMD efficiency, useful lane-slots divided by issued lane-slots, drops below 100%.

The cost rule is simple: a divergent if/else costs the sum of both paths, not one of them. A warp where every lane agrees, even if different warps go different ways, pays only for the path it takes.

Add one block: reconvergence, nesting and loops

Where do paths rejoin? The natural place is the immediate post-dominator of the branch: the first instruction that every path from the branch must pass through. For an if/else that's the line after the closing brace. Classic GPUs track this with a small hardware reconvergence stack. At a divergent branch it pushes the reconvergence point along with the mask for each side, runs one side, then pops to run the other, and finally pops back to the full mask.

Nesting multiplies. A divergent if inside a divergent if can split a warp four ways, each part running with a fraction of the lanes.

Loops diverge on trip count. If lane 0 loops once and lane 5 loops four times, the warp keeps executing the loop until its last lane finishes, with finished lanes masked off:

Worked example: a warp where 31 lanes loop 10 times and one lane loops 100 times runs the loop body 100 times. Lane-slots issued: $100 \times 32 = 3{,}200$. Useful: $31 \times 10 + 100 = 410$. SIMD efficiency is about 13%. One slow lane made the whole warp slow, the same "wait for the slowest lane" rule as loads in Chapter 1.3.

The whole machine: make conditions warp-uniform

Divergence is a property of warps, not of your program. A condition that's the same for all 32 lanes of a warp is warp-uniform and costs nothing extra, even if half the warps take each side. So the main tool is remapping work so that similar work lands in the same warp:

ConditionDivergent?Why
if (threadIdx.x % 2 == 0)every warpneighbouring lanes disagree
if (threadIdx.x < 16)warp 0 only (block of 64)lanes 0–15 vs 16–31 split warp 0; warp 1 is all false
if ((threadIdx.x / 32) % 2 == 0)neverconstant within each warp
if (i < n)at most one warponly the warp straddling n

When the data itself decides the branch (sparse inputs, rays hitting different materials, particles in different states), you can't pick the condition. Instead you reorder the data: sort or bin the work items so that items taking the same path sit next to each other. That turns divergence into a data-movement problem, which Part 3's compaction and sorting primitives solve.

Our simulator counts divergence exactly this way. Each evaluation of an if, while or for condition is lined up across the lanes of a warp. If the lanes disagree, that warp-level branch is counted as divergent.

Reality

Independent thread scheduling. From Volta onwards, NVIDIA GPUs give every thread its own program counter and call stack instead of one stack per warp. The scheduler still issues one instruction for a group of lanes at a time, so divergent paths are still serialised and still cost the sum. But it may now interleave the two paths rather than finishing one before starting the other, and reconvergence isn't guaranteed at the post-dominator. Two consequences:

  • Algorithms where lanes of the same warp wait on each other, such as a spin-lock taken by one lane, no longer deadlock. Under the old stack model they could, because the lane holding the lock might never get scheduled.
  • Code that relied on implicit lockstep ("warp-synchronous programming") is unsafe. Use explicit __syncwarp() and the *_sync warp intrinsics, which name the lanes that must participate.

Hardware has also tried to recover the lost lanes directly. One of this Part's paper chapters, Dynamic Warp Formation, regroups threads from different warps that sit at the same instruction. And NVIDIA's Ada generation added Shader Execution Reordering for ray tracing, which regroups threads by the work they're about to do.

Companion readingH&P 7th ed., Chapter 4, the section on conditional branching in GPUs, describes the mask stack and post-dominator reconvergence in the book's own terms.

Worked examples

Example 1: tracing the reconvergence stack

Code (a 4-lane warp, for readability): A; if (c) { B; } else { C; } D; with c true for lanes 0 and 2.

Trace. The stack starts with one entry: (mask 1111, next A).

  1. Run A with mask 1111. At the branch, lanes disagree. Replace the top with the reconvergence entry (1111, D), then push (0101 → lanes 1 and 3, next C) and (1010 → lanes 0 and 2, next B).
  2. Pop (1010, B): run B for lanes 0 and 2. Reaching D, pop.
  3. Pop (0101, C): run C for lanes 1 and 3. Reaching D, pop.
  4. Top is (1111, D): run D with every lane.

Cost: A + B + C + D issue slots, with B and C at half efficiency. A nested divergent branch inside B would push two more entries above the B entry and pop them before C runs: the stack depth equals the nesting depth, and each level halves (or worse) the active lanes.

Example 2: fixing a divergent condition by remapping

Setup. A kernel processes complex numbers stored as interleaved floats (re, im, re, im, …). One thread per float, and the code does if (i % 2 == 0) handleReal(); else handleImag();. Each handler is 20 instructions.

As written: every warp has 16 even and 16 odd lanes: 40 instructions per warp at 50% efficiency.

Remap: let thread $t$ of a 64-thread group handle element 2t if it's in the first warp of the group and 2(t - 32) + 1 if it's in the second. Now warp 0 does all the real parts and warp 1 all the imaginary ones: 20 instructions per warp, and no divergence. Same work, half the instructions.

The price is in memory: lane $k$ of warp 0 now reads element $2k$, so the warp's addresses are 8 bytes apart instead of 4, and it touches twice as many sectors (Part 2). Often the better fix is one thread per complex number, handling both parts. When a condition depends on the thread index, look for a mapping that makes it depend on the warp index instead.

Example 3: expected divergence cost of a data-dependent branch

Setup. Lanes independently take the then path (cost $a$) with probability $p$, else the else path (cost $b$).

Derivation. A warp pays $a$ if all lanes are true, $b$ if all are false, and $a + b$ otherwise:

$$E[\text{cost}] = p^{32} a + (1-p)^{32} b + \big(1 - p^{32} - (1-p)^{32}\big)(a + b)$$

Read it. For any $p$ not very close to 0 or 1, both 32nd powers vanish and the cost is $a + b$: a data-dependent branch costs the sum of both paths in almost every warp. For $p = 0.01$: $(0.99)^{32} = 0.725$, so 27.5% of warps still pay for the rare path. Only below about $p = 0.002$ does the rare path mostly disappear ($0.998^{32} = 0.938$).

Rule. The ideal cost is $pa + (1-p)b$ per lane-average. The gap between that and the formula above is what sorting, compaction or warp-uniform remapping can recover.
