The real problem

A convolutional network layer convolves C input channels with M filters, each C × K × K, producing M output maps. Written as loops it's a seven-deep nest (batch, output channel, input channel, output row and column, filter row and column) with irregular reuse. The GPU's best kernel by far is the GEMM of Part 4. Can a convolution layer become one?

The smallest idea: im2col

Each output value is a dot product: a filter (C·K·K weights) with the C·K·K input values under it. So:

  • lay out every filter as a row of a matrix $W$ (M × CK²);
  • lay out, for every output position, the input values under the filter as a column of a matrix $X$ (CK² × HoWo): this is im2col, "image to columns";
  • then the whole layer is one matrix product, $Y = W X$ (M × HoWo).

FLOPs: $2 \cdot M \cdot CK^2 \cdot H_oW_o$, all in a GEMM that libraries run at near peak, on tensor cores. The cost is memory: X duplicates each input value up to K² times (neighbouring output positions share inputs). For a 3 × 3 filter, X is about 9× the size of the input.

Add one block: training, too

Training needs two more products per layer, and both are GEMMs with the same matrices:

  • gradient with respect to the weights: $\partial L / \partial W = (\partial L / \partial Y)\, X^\top$;
  • gradient with respect to the input: $\partial L / \partial X = W^\top (\partial L / \partial Y)$, then col2im scatters it back, summing the K² copies of each input position (a scatter-add, which needs atomics or a gather formulation).

So a convolutional network's forward and backward passes are three GEMMs per layer. That's why GPUs, and then tensor cores, made deep learning practical, and why Part 4's GEMM ladder is the most important kernel in this course.

The whole machine

The explicit im2col writes and re-reads a matrix about K² times the input's size: pure memory traffic before the GEMM starts. In the exercise, mapping threads to consecutive columns of X makes the writes coalesce (about 0.87); mapping them to rows strides every write by the row length (about 0.18 coalescing, 5× the sectors).

Production libraries avoid materialising X altogether: implicit GEMM computes the im2col indices on the fly while loading GEMM tiles into shared memory, so the tile loader reads the input directly. The GEMM's tiling (Part 4) still applies; only the address computation in the loads changes. cuDNN and CUTLASS's convolution kernels work this way.

Reality

  • Other algorithms: FFT-based convolution wins for large filters; Winograd transforms cut multiplications for 3 × 3 filters by about 2.25× at some cost in numerical accuracy. Libraries benchmark and pick per layer (cuDNN's autotuner), which is one source of non-determinism (Chapter 9.1).
  • Data layout matters: NHWC (channels last) suits tensor-core implicit GEMM better than NCHW, which is why frameworks convert layouts.
  • Modern vision models increasingly use attention (Chapter 7.2), which is matrix multiplication without the im2col step; the GEMM is the constant.

Companion reading: PMPP 4th ed., Chapter 16 (Deep learning); S. Chetlur et al., "cuDNN: Efficient Primitives for Deep Learning" (2014).

Worked examples

Example 1: im2col by hand

Input: one channel, 3 × 3: [[1, 2, 3], [4, 5, 6], [7, 8, 9]]; K = 2; output 2 × 2.

X (4 rows for (ky, kx) ∈ {(0,0), (0,1), (1,0), (1,1)}, 4 columns for output positions (0,0), (0,1), (1,0), (1,1)):

row (0,0): 1 2 4 5
row (0,1): 2 3 5 6
row (1,0): 4 5 7 8
row (1,1): 5 6 8 9

With filter W = [1, 0, 0, 1] (main diagonal), Y = W X = [1 + 5, 2 + 6, 4 + 8, 5 + 9] = [6, 8, 12, 14]: each output is top-left plus bottom-right of its window. ✓ Notice 5 appears four times in X: the K² duplication.

Example 2: where the time goes in a lowered layer

Layer: C = 256, M = 256, 3 × 3, 28 × 28 outputs, batch 32, FP16, on a GPU with 300 TFLOP/s (tensor) and 2 TB/s.

GEMM: 2 × 256 × 2,304 × 25,088 = 29.6 GFLOP → 0.10 ms at peak. Explicit X: 2,304 × 25,088 × 2 bytes = 116 MB, written then read: 232 MB → 0.12 ms. The copy costs more than the GEMM. Implicit GEMM removes it, which is why it's the default in cuDNN and CUTLASS for tensor-core convolutions.
