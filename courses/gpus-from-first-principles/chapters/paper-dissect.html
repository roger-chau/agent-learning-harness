The work
Z. Jia, M. Maggioni, B. Staiger, D. P. Scarpazza. "Dissecting the NVIDIA Volta GPU Architecture via Microbenchmarking." Technical report, Citadel, 2018 (arXiv:1804.06826).
arXiv · Long, and organised as a reference. The reading guide picks a path through it. The same team later published similar reports on Turing and on the Graphcore IPU.

The problem

NVIDIA publishes peak numbers and a programming guide, but not the details that decide whether code is fast: cache latencies and sizes, how the register file is banked, how instructions are encoded and scheduled, how tensor-core operations break down. A trading firm that needed every last microsecond decided to find out for itself, by measurement, and then published what it found.

The key idea

Design tiny programs whose run time depends on exactly one hidden property, then vary one parameter and watch where the time changes. The classic is the pointer chase: an array where each element holds the index of the next one to read. Every load depends on the previous one, so nothing overlaps, and time per access is pure latency. Sweep the array size: while it fits in L1, each access costs L1 latency; past L1's capacity, L2 latency; past L2's, DRAM. The steps in the curve are the capacities, and the plateaus are the latencies.

The same pattern, one variable at a time, measures line sizes (sweep the stride), associativity (sweep conflicting addresses), bank counts, throughput per instruction, and more. The paper applies it systematically, and adds something unusual: it reverse-engineers the instruction encoding, so it can read and patch the machine code itself.

Reading guide

  • The memory hierarchy chapter: the pointer-chase plots. Learn to read a latency-vs-size curve; it's the most reused technique in the paper.
  • The register file and instruction encoding: Volta moved to 128-bit instructions with scheduling control information inside them, and the paper finds a register file with two 64-bit-wide banks. It shows how a register bank conflict costs a cycle, and how reordering register numbers removes it. This is a compiler's job (Part 6), and a reason hand-tuned assembly can still beat compilers.
  • The tensor core section: how one warp-level matrix instruction maps onto the hardware, and the fragment layouts (compare with Chapter 4.5).
  • Skim the rest: it's a reference for when you need it.

Reproduce it

Read a pointer-chase curve: given (array size, cycles per access) measurements, find the plateaus and where they end. The paper project after this chapter goes further: the simulator's spec is hidden and randomised, and you measure it.

What happened next

Microbenchmark studies became a standard companion to every new GPU generation, from academic groups and companies alike, and they feed directly into performance models, compilers and tools. Performance engineers keep their own suites too: when a new GPU arrives, the first job is to check the numbers the code depends on. Knowing how to design a measurement that isolates one effect is the core skill behind all of it.
