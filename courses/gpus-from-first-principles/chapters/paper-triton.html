The work
P. Tillet, H. T. Kung, D. Cox. "Triton: An Intermediate Language and Compiler for Tiled Neural Network Computations." MAPL 2019 (ACM SIGPLAN Workshop on Machine Learning and Programming Languages).
Find it on Google Scholar · Short (a workshop paper). Read it alongside the official Triton matmul tutorial, which shows the same ideas in today's Python syntax.

The problem

Every new neural network layer needed fast GPU kernels, and there were two bad options. Vendor libraries (cuBLAS, cuDNN) were fast but fixed: anything they didn't cover ran slowly. Writing CUDA by hand meant doing everything Part 4 taught you, per operation and per GPU: tiling, shared memory, synchronisation, coalescing. Existing compilers either worked on whole tensors with a fixed menu of schedules, or expected you to describe the schedule in detail.

The key idea

Program at the level of tiles, and let the compiler handle everything below a tile. In Triton, a kernel is written for one program instance that computes one block of the output, with operations on whole tiles (load a BLOCK_M × BLOCK_K tile, dot two tiles, store a tile). The programmer chooses how work is split into tiles; the compiler decides how threads, warps, registers and shared memory implement each tile operation.

The paper introduces Triton-C (a C-like front end with tile types), Triton-IR (an LLVM-based IR whose values are tiles), and a compiler whose passes include:

  • machine-independent: tile-level peephole optimisations, prefetching (software pipelining, Part 4 and Chapter 6.4);
  • machine-dependent: hierarchical tiling onto warps and threads, memory coalescing, shared-memory allocation and automatic insertion of barriers;
  • and an auto-tuner that searches tile sizes and other parameters per problem.

The result: matrix multiplication close to vendor libraries, and fused or unusual operations that the libraries didn't offer, from a few dozen lines of code.

Reproduce it

One tile-level decision the compiler can't make for you: the order of program instances. Triton's matmul tutorial launches programs in groups of rows (GROUP_SIZE_M), so programs running at the same time reuse the same panels of A and B from L2. Implement that mapping, and measure the working set it saves.

What happened next

OpenAI released Triton 1.0 in 2021 with a Python front end, and it became the main way to write custom GPU kernels for deep learning. PyTorch 2's compiler (TorchInductor) generates Triton code for fused operations by default. The compiler was later rebuilt on MLIR, with tile layouts as first-class concepts, and gained backends for other vendors' GPUs. Tile-level programming spread further: CUTLASS's CuTe layouts, and other tile languages for GPUs and accelerators followed the same idea. For a GPU compiler engineer, Triton's internals are one of the most relevant codebases to know.
